# Megaton Menu Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Faithfully port Megaton's non-Steam menus to RmlUi while preserving this port's game, settings, input, saves, maps and release compatibility.

**Architecture:** An optional C++17 UI target owns RmlUi documents, navigation and animation behind a C interface. Shared C actions retain game policy; the Build SDL layer supplies a retained GL presentation context and a final overlay callback. Classic menus remain the fallback and the default in builds without the new UI.

**Tech Stack:** C99, C++17, CMake 3.24+, SDL2, RmlUi 6.3, FreeType, compatibility OpenGL, CTest.

**Spec:** `docs/superpowers/specs/2026-10-23-megaton-menu-migration-design.md` (approved 2026-10-23).

## Global Constraints

- Add opt-in `DUKE3D_RMLUI`, default OFF during migration.
- Keep the game C99. Enable C++17 only when building the optional UI target.
- The new UI requires compatible GL presentation; true no-GL runs, including `DUKE3D_POLYMOST=OFF`, keep the existing classic menus.
- Request GL presentation without changing the selected game renderer or saving a different renderer setting.
- Do not change gameplay, demo/network synchronization, save formats, profile locations, Build editor UI, game renderers or GL draw-path selection as an incidental effect.
- Removing Steam must remove service dependencies and actions, not leave dead buttons, disabled Steam placeholders, polling managers or SDK stubs.
- Use temporary profiles, never the user's live config. Inspect the Steam installation read-only and never commit its private files.
- Keep the UI opt-in until the parity checklist is complete and the user accepts it.
- Short subsystem-prefixed commits, no commit metadata; leave existing untracked Python cache directories alone.

## Review Focus

- Resuming with a held button or an opening/closing press must not fire or accept twice: Task 4 pins handoff, release and repeat behavior.
- Missing assets or failed GL initialization must preserve a usable classic menu and saved preferences: Tasks 1, 2 and 8 inject these failures.
- HiDPI, letterboxing and resize must keep drawing, hit testing and clipping aligned: Tasks 3 and 4 pin exact transforms and corner clicks.
- Capturing or redrawing a paused frame must include the current overlay once, with the same fade and no gameplay action: Task 2 pins callback order and Task 8 checks actual pixels.
- Editing save names or selecting maps with non-ASCII/markup characters must preserve safe filenames and escape UI text: Tasks 5 and 6 pin literal text and validation.
