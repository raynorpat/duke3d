# Polymost Renderers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Ken Silverman's Polymost renderers from JFBuild's 2004 import to the game. They are renderer 1 (solid colour), 2 (software polygons) and 3 (OpenGL), beside the unchanged classic renderer 0. The renderer is chosen in `duke3d.cfg`, and `-renderer N` overrides it.

**Architecture:** `polymost.c` is vendored into `source/build/` and `#include`d by `engine.c` under `POLYMOST`, as in JFBuild. The engine calls into it at JFBuild's hook points. `sdl_driver.c` gets a second video path for renderer 3: an SDL2 window with an OpenGL legacy context, drawn at the drawable's real size. Renderers 0–2 keep today's 8-bit surface path. Duke-side changes are small: the setting, the option, fades, the status bar, and ANM frames.

**Tech Stack:** C (the engine's C dialect), SDL2 2.x, OpenGL 1.1 fixed-function through `SDL_opengl.h`, CMake ≥ 3.24, CTest.

**Spec:** `docs/superpowers/specs/2026-10-19-polymost-design.md`

**Upstream source:** `https://github.com/jonof/jfbuild`, commit `db5ed47a8b327754afb9b2ecc8c755f04e9e9f2c`. Use `src/polymost.c` and, for reference only, `src/engine.c` (hook sites) and `src/sdlayer.c` (`showframe`'s GL fade quad, around line 809). A checkout is at `$SCRATCH/jfbuild/src`. Otherwise `git clone https://github.com/jonof/jfbuild && git checkout db5ed47`.

## Global Constraints

- Renderer numbers: **0** classic, **1** Polymost solid colour, **2** Polymost software, **3** Polymost OpenGL. The default is **0**.
- Renderer 0 with the default config is unchanged. `render_e1l1` keeps checksum `e0517697`, and every existing test passes on every version (1.3D, 1.3D shareware, 1.4, 1.5).
- No game-logic change. The demo sync tests pass. The attract demos stay in sync in renderers 1–3 (checked by eye).
- Out of scope: hightile, kplib, md2, defs, OSD, `USE_PMDBGKEYS`, and the editor (`build`). The editor must still compile and run with renderer 0.
- OpenGL: legacy fixed-function context, through `SDL_opengl.h` (never `<GL/gl.h>`/`<GL/glext.h>`). On macOS define `GL_SILENCE_DEPRECATION`.
- Renderer 3 draws at the window's drawable size (`SDL_GL_GetDrawableSize`, with `SDL_WINDOW_ALLOW_HIGHDPI`). `xdim`/`ydim` equal that size.
- Classic-look GL defaults (my call): `gltexfiltermode = 0` (`GL_NEAREST`), `glusetexcompr = 0`, `glanisotropy = 1`.
- `polymost.c` is retyped with `tools/retype_long.py` (`long` → `int32_t`). Values holding addresses are `intptr_t` or real pointers, as in the rest of the engine. Its x86 `ftol`/`dtol` pragmas use the C fallback.
- Every local change to vendored files goes into `source/build/VENDORED.md`.
- Commits follow `AGENTS.md`: `subsystem: what it does`, one or two lines, then the `Co-Authored-By` trailer.
- Test data: the real 1.3D data is at `~/Downloads/DUKE3D`. Symlink it into a scratch directory and never run the game in place. Configure with `-DDUKE3D_GRP=<path>` so data-gated tests register.

## Review Focus

1. **Fades with no redraw in renderer 3.** Logo and title screens are drawn once, then `palto` steps the fade. In GL they must fade smoothly, not show black or jump to the end. Pinned in Task 5 (manual check of the 1.3D logo before the attract demos).
2. **Persistence across GL swaps.** The status bar, its piecewise updates, the view border and permanent rotatesprites must stay on screen every frame in renderer 3. Pinned in Task 5 (manual check, playing with the status bar visible at screen size < full).
3. **Window size changes in renderer 3.** Starting fullscreen, toggling fullscreen (Alt+Enter) and Retina displays: `xdim`/`ydim` follow the drawable, and there's no overflow past `MAXXDIM`/`MAXYDIM`. Pinned in Task 3 (`sdl_driver_smoke` checks the clamp, plus a manual toggle check).
4. **Bad renderer values or no GL.** `Renderer = 7` in the cfg, `-renderer x`, or a machine where the GL context fails. The game clamps to 0–3 and falls back to renderer 0 with a message, without exiting. Pinned in Task 2 (clamp test) and Task 3 (`gl_fallback` test).
5. **`setviewtotile` paths in renderers 1–3.** Camera screens (TILE_VIEWSCR), mirrors and screen tilt (rotating while dying) must draw correctly. Pinned in Task 2 (manual: E1L1 camera room and mirror in renderer 2) and Task 4 (same in renderer 3).

### Task 3: OpenGL video path in sdl_driver.c

**Interfaces:**
- Consumes: `setrendermode`, `polymost_glreset`, `rendmode`.
- Produces:
  - `int setgamemode_gl(char davidoption);`: in `sdl_driver.c`, declared in `display.h`. It creates or switches the window to an OpenGL context sized to the drawable, sets `bpp = 32`, `xdim = xres` and `ydim = yres` (the drawable size, clamped to `MAXXDIM`×`MAXYDIM`), `qsetmode = 200` (JFBuild's "3D mode" meaning, which `nextpage` and the clears test), and `frameplace = 0`. It fills `glinfo` from `glGetString(GL_EXTENSIONS)`: `bgra` = `GL_EXT_bgra`, `clamptoedge` = `GL_EXT_texture_edge_clamp` or `GL_SGIS_texture_edge_clamp`, `texcompr` = `GL_ARB_texture_compression`, `maxanisotropy` = `GL_MAX_TEXTURE_MAX_ANISOTROPY_EXT` if that extension is present, else 1. It then calls `setrendermode(3)` and `polymost_glreset()`. It returns 0 on success. On any SDL or GL failure it returns -1 and leaves the 8-bit path working: the caller falls back with `setgamemode(ScreenMode, ScreenWidth, ScreenHeight)` and prints `"OpenGL renderer unavailable (%s); using the classic renderer."` with `SDL_GetError()`.

  - `MAXXDIM 7680`, `MAXYDIM 4320` (my call: room for 8K drawables). Larger drawables are clamped and drawn into a viewport of that size.
  - The fullscreen toggle (`attempt_fullscreen_toggle`) in GL re-reads the drawable size and redoes the `xdim`/`ydim` and `ylookup` setup and `polymost_glreset()`.
- Video attributes: `SDL_GL_CONTEXT_PROFILE_MASK` is left at its default (legacy/compatibility), `SDL_GL_DOUBLEBUFFER = 1`, `SDL_GL_DEPTH_SIZE = 24`. Swap interval 1, falling back to 0.
