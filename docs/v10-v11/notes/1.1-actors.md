# actors.c: 1.1 shareware compared with 1.3D shareware

Scope: everything `docs/v13d/notes/1.3d-actors.md` covers, from `sw11.bin`
(`0x23580`–`0x31b6f`) against `sw13.bin` (`0x24d30`–`0x33c4f`). Addresses are flat image
addresses (base `0x10000`). "1.3D" means the 1.3D shareware EXE. Ledger rows are
`G11-Ann`. The 1.1 `ps` stride is `0x34e`. Player fields are named from the 1.1 `player_struct`
map in `docs/v10-v11/reference.md` ("player_struct (1.1)"). Tile names come from the 1.1 `DEFS.CON` when
they differ from `names.h`: 2500 `THROWFLAME`, 2710 is `BOSS3` in 1.1 (1.3D `BOSS2`), 1920
`FATGUY` (1.3D `COMMANDER`), weapon 7 `FLAMETHROWER_WEAPON`.

## Method

1. **Pairing.** fmatch (`fmap11.txt`) pairs the small helpers. The movers were paired by
   the 1.1 `domovethings` call list (`0x20ff0`) and by size. 1.1's source order is
   moveeffectors (`0x29b30`), moveactors (`0x2e1f0`), moveexplosions (`0x30a80`); 1.3D's
   is moveactors, moveexplosions, moveeffectors.
2. **Token diff.** Each pair was disassembled and reduced to a stream of constants, field
   offsets (sprite, hittype, sector, wall), branch kinds and calls (mapped through fmatch),
   then diffed with `difflib`. Registers and global addresses drop out, so a diff that
   only shows `oNN` against `#NN`, `#552` against `#4 o8` (the `ps` stride) or a reordered
   operand is code generation. Every other hunk was read in the disassembly.
3. **Picnum switches** (moveactors, moveexplosions, moveweapons, moveeffectors' SE lotag
   tree) were walked for every value 0–4095 in both EXEs, and the case bodies were
   token-diffed one by one.
4. **Map reach.** A scan of the six 1.1 maps (sprite picnums, SE lotags) shows which
   differences shipped levels reach. Of note: 51 CAMERA1, 17 HEAVYHBOMB, 16 pool balls, 6
   RECON, 6 FIREEXT, 105 RAT, 17 FEM/PODFEM sprites, 7 STEAM, 2 CEILINGSTEAM, 1 DUKECAR;
   SE lotags 2 (14), 24 (182), 30 (4), 34 (1), 36 (3). There is **no SE6, SE14 or SE17**
   and no GREENSLIME, EGG, OOZFILTER or FIREVASE sprite in the shipped maps.

## 3. GREENSLIME (`0x2f3ad`, 1.3D `0x2c74e`)

Compared at decompile level. 1.1 differs in these points (no GREENSLIME in the shipped
maps):

- **On a player (`T1 == -4`).** Fire (`bits&4`) frees the player: `kickback_pic = 0`,
  `xvel = 128`, `zvel = (100 - horiz)*16 - 512`, `T1 = 0`, `somethingonplayer = -1`. There is no
  weapon or alive test and the slime survives. 1.3D kills the slime (8 gibs, sounds 0x95
  and 0x45, a krand < 32 spawn of 1226, frag count) when the player is alive and holds
  any weapon but KNEE, HANDBOMB, TRIPBOMB or HANDREMOTE with ammo.
- Damage tick at `T4 == 5`: `extra -= 5` (1.3D `5 + (krand&3)`).
- No camera (`newowner`) reset when it grabs the player.
- Gulp list adds 1425 (1.1 `DUMMYDUKE`) and 1820 to LIZTROOP, PIGCOP, LIZMAN.
- Moving: the sector lotag is set to 0 around `ssp` when it is 1, then restored.
- `T1 == 2` uses the sector's ceilingz and no `ceilingstat&1` test (1.3D: hittype
  ceilingz, or ceilingstat&1).
- Idle sound when `(krand&255) == 0` (1.3D `(krand&511) == 0`).
- Death when hit: `extra < 0` → global sound 0x95, kill count `actors_killed++`, `T1 = -3`
  (shrink, then 8 gibs per tic until gone); otherwise sound 0x94. 1.3D has the freeze
  path (`T1 = -5`) and 8 gibs at once.

ceilingspace, floorspace, addammo, ssp, insertspriteq, lotsofmoney, ms (fmatch exact or

## 5. Not checked

- The 1.1 `ps` field names (5d). Rows give offsets.
- GREENSLIME was read at decompile level, not instruction by instruction.
- SE17 and SE30's player paths were read in the disassembly at branch level only.
- CHAINGUN (2536) as a moving projectile: what spawns it is in `shoot` (player.c, 5d).
