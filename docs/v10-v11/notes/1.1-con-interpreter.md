# 1.1 vs 1.3D: CON interpreter differences

I compared `parse` in 1.1 (`0x350a0`, jump table `0x34ed0`, opcodes 2–93) against 1.3D
shareware (`0x370a0`, jump table `0x36ec0`, opcodes 2–97) case by case. I used the
Ghidra decompiles and checked each claimed difference in the capstone disassembly at the
address given. 1.1's `player_struct` is `0x34e` bytes (1.3D: `0x552`). Where a field is
named below, it is named from its use, not from a full struct map.

1.1 globals:
- `insptr` `0x12edc0`; `g_sp` `0xd2474`; `g_t` `0xd2470`; `g_i` `0xd248c`; `g_p` `0xd248e`; `g_x` `0xd247c`; `killit_flag` `0x131586`
- `ps[]` `0x1162e0`; `sprite[]` `0x1a7030`; `sector[]` `0x21f330`; `hittype[]` `0xda840` (stride `0x47`)
- `parseifelse` `0x34ea0`; `krand` `0x67a71`; `spritesound` `0x52a60`; `spawn` `0x17300`; `badguy` `0x11a30` (a picnum switch)

## New opcodes

| Opcode | 1.1 behavior | Evidence |
|---|---|---|
| `shadeto` (65) | `insptr++; g_sp->shade += 2*ksgn(*insptr - g_sp->shade); insptr++;` with byte arithmetic | `0x37641`–`0x37672` (`add ebx,ebx; sbb eax,eax; cmp eax,ebx; adc al,0; add al,al; add [shade],al`) |
| `ifplayersl` (68) | `parseifelse(word[0x13053e] < *insptr)`. 1.1's `resetplayer` tests the same word with `< 2`, where 1.3D tests `ud.multimode`. EDuke32 uses `numplayers`. Which one it is stays open. | `0x35fcd`–`0x35fee` |
| `endoflevel` (69) | `ps[g_p].timebeforeexit = arg; ps[g_p].customexitsound = -1; insptr += 2`. Unlike 1.3D `endofgame`, it does **not** set `ud.eog = 1`. | `0x35fff`–`0x3605a`; 1.3D `endofgame` stores 1 to `0x14d9a7` |
| `ifhitedge` (83) | `parseifelse((hittype[g_i].movflag & 0xc000) == 0x4000)` (unused by the shipped CONs) | `0x38035`–`0x38067` |
| `rise` (84) | `insptr++; xoffset = yoffset = 0; zvel -= 176; z += zvel; if (zvel < -6144) zvel = -6144` (unused) | `0x35a4f`–`0x35a93` |
| `debugprint` (93) | `insptr++` only | `0x35860` |

## Same as 1.3D (checked)

- **C-002 `sizeto`:** `abs(j) > 2` gate (decompile `case 0x1c`).
- **C-003 `addweapon`:** no knee switch after `addammo` (`case 0x17`).
- **`addammo`:** has the knee check.
- **C-004:** no camera reset.
- **C-006:** single player keeps running.
- **C-007 `ifp` bit 512:** `curr_weapon == 0 && kickback_pic > 0` (`ps+0x29e`, `ps+0x2be`).
- **`ifp`:** the other bits and their test order: 8, 16, 32, 1, 2, 4, 64, 128, 256, 512, 1024, …, 65536.
- **C-008 `ifspawnedby`:** owner test included (`case 0x3b`).
- **`ifcansee`:** 1.1 drops 1.3D's distance comparison, but that comparison only ever re-assigned 0, so it had no effect.
- **The rest:**
  - `ifrnd`, `ifcanseetarget`, `ai`, `action`, `move`
  - `ifpdistl`/`ifpdistg` (SLEEPTIME `0x600`)
  - `else`, `state`, `{`, `}`, `killit`
  - `palfrom`, `pstomp`, `operate`, `ifawayfromwall` (±108)
  - `quote`, `money`, `wackplayer`, `guts`, `hitradius`, `shoot`
  - `sound`, `soundonce`, `stopsound`
  - all simple ifs and setters

C-009 (`ifgotweaponce`) and C-010 (`respawnhitag`) do not apply, because 1.1 has neither
keyword.

## Outside `parse`: checked here for the EDuke32 hypotheses

- **LIZTROOP spawn:** `spawn`'s badguy init (`0x193d0`–`0x19410`) does
  `if (pal) extra <<= 1; else if LIZTROOP* pal = 22`. This matches 1.3D sw
  (`0x1a2b3`–`0x1a2f3`), which is our existing `< GAMEVER_14` path. 1.0 is the same
  (`0x19302`–`0x19342`). One more difference in the same block: GREENSLIME gets
  `extra = 10` (`0x193ca`; 1.0 `0x192fc`). 1.3D gives it 1 (`0x1a2ad`).
- **RPG smoke:** 1.3D's `moveweapons` spawns SMALLSMOKE behind an RPG (`0x29f1e`–`0x29f66`).
  1.1 (`0x27ed0`) and 1.0 (`0x27890`) have no such spawn. Their only SMALLSMOKE spawn is
  for picnum 2500 in lotag-2 sectors (1.1 `0x2854c`–`0x2857d`).
