# game.c: 1.0 shareware compared with 1.1 shareware

Scope: every game.c function in `1.1-game.md`, plus the menus file between loadpheader and
setpal. Each `sw11.bin` function is compared with its partner in `sw10.bin`. 1.1 is the
reference here, and its differences from 1.3D are in `1.1-game.md`. Addresses are flat
image addresses (base `0x10000`). Ledger rows are `G10-Gnn`.

## Method

1. **Pairing.** `tools/fmatch.py sw11.bin sw10.bin` pairs all 70 game.c functions
   (31 exact, 39 by order) and all 12 functions in the menus range. 1.0 has one function
   that 1.1 lacks, at `0x37f30` (section 3).
2. **Normalized diff.** Each pair was disassembled with capstone and normalized as
   follows, then diffed:
   - registers dropped
   - calls mapped through the fmatch pairs
   - 1.0 globals mapped to 1.1 by a vote over all aligned instructions (2406 addresses)
   - `ps` offsets mapped through the 1.0 `player_struct` map (`reference.md`)

   The tools are in the scratchpad, `t5e/fd10.py` and `t5e/gmap10.py`. Every hunk that
   was more than register allocation, an operand swap or `CLIPMASK` spelling was read in
   the disassembly or in Ghidra decompiles. (1.0 engine calls pass cliptype 0 or 1 and
   hitscan takes none, E10-002/E10-005. Those map to 1.1's `0x10001`/`0x1000040`.)
3. **spawn.** The picnum compare tree was walked for every value 0–8191 in both EXEs
   (1.1 head `0x17667`, 1.0 `0x175f7`). Landings were compared through the instruction
   alignment, and "bare return" landings were folded together.
4. **Map reach** is from the six 1.0 maps in `DUKE3D.GRP`. They differ from the 1.1 maps:
   only E1L6 is byte-identical.

## 1. spawn (`0x17300` / `0x17290`)

The pre-switch code is identical. The tree differs for two picnums only:

| Picnum | 1.1 | 1.0 | 1.0 maps |
|---|---|---|---|
| SPACEMARINE (1353) | `extra = 20; cstat \|= 257`, stat 2 (`0x1875b`) | bare return (`0x179df`) | 1 sprite |
| CHAIR3 (680) | `cstat \|= 257; clipdist = 32`, stat 0 (`0x18792`, with MONK and the rest of that group) | bare return (end of function, `0x1ab92`) | 0 |

Case bodies that differ:
- **Hidden sprites.** 1.1 hides these with cstat bit 15. 1.0 hides them by size alone:
  `xrepeat = yrepeat = 0`, and for MUSICANDSFX/RESPAWN and SEENINE also `cstat = 0`.
  - MUSICANDSFX and RESPAWN: 1.1 `0x18dc9`, 1.0 `0x18cef`–`0x18d01`
  - WATERBUBBLEMAKER: `0x19311` / `0x19245`
  - MASTERSWITCH: `0x1937b` / `0x192a7`
  - LOCATORS: `0x1956a` / `0x19480`
  - ACTIVATOR(LOCKED): `0x1958b` / `0x194a2`
  - SECTOREFFECTOR: `0x19acb`
  - The SEENINE group with `xrepeat <= 8`: `cstat = 0x8000` against `0`, `0x1ab1e` /
    `0x1aa29`
  - With `recstat == 1`, the SE "show" path: 1.1 sets size 64 and clears bit 15
    (`0x19c71`); 1.0 sets the size only (`0x19b70`).

  No reader of bit 15 on these sprites was found, so the difference is expected to show
  only in saved sprite fields.
- **Bosses** (`0x1942d` / `0x1935f`). 1.0 gives BOSS1, BOSS2 and 2710 size 80 and
  clipdist 127 always. 1.1 shrinks BOSS1 (size 40, clipdist 80, `extra >>= 2`) when
  `volume_number > 0`, which happens only on user maps (volume 3).
- **Same in both:** BLOODPOOL's four corner probes (1.0 doesn't seed `updatesector`'s
  start sector, see section 5), CRANE, the enemy shade, and GREENSLIME (G11-G19 already
  says 1.0).

## 2. Cheats, command line, keys

- **cheats** (`0x1c7f0` / `0x1c630`). The table at `0xc666a` has **20 entries**, the
  loop bound is `0x13`, and there is no `clip`. processinput (`0x46d5d`, `0x46fe7`) and
  ifsquished (`0x239f6`) have no clipping branches either.
  - `stuff` and `items` give holoduke 1600, not 2400 (`0x1cafd`, `0x1cee0`).
  - `stuff` doesn't set `inven_icon = 1`.
  - `monsters` still cycles its counter (`0xd1f7f`, `0x1d127`–`0x1d15c`), but nothing
    reads it. 1.1's moveactors reads it to hide (1) or restore (2) badguys in single
    player and skips their CON while hidden (`0x2e327`, `0x2ebcb`).
  - Cheat entry is gated on a menu-range test (`0x12ed80` not in 360–369) where 1.1
    tests `gm`. This is UI.
- **checkcommandline** (`0x1e530` / `0x1e210`): `/t` always turns on both respawn flags
  (`0x130f03`, `0x130eff`). There is no `/t1` or `/t2`.
- **nonsharedkeys** (`0x1d4f0` / `0x1d2b0`): no AutoRun key and no Toggle_Crosshair key.
  AutoRun is a per-player synced bit in 1.0 (`1.0-sector.md`). Cheat-phase entry tests
  `cheat_phase != 0`, not `== 1`. The music-volume key has no lockout test.
- **wallswitchcheck** (`0x171e0` / `0x17170`): the 162–167 range ends at 165
  (`cmp 0xa5` at `0x171e1`). TECHSWITCH (166/167) is not a wall switch in 1.0
  (`1.0-sector.md`), and the 1.0 maps have none.

## 3. HUD, menus, title

- **No crosshair.** 1.0 displayrest (`0x14e60`) never draws CROSSHAIR (1.1 `0x15528`),
  and there is no `ud.crosshair` (Formats: 1.0 has 4 trailing save scalars).
- 1.0 displayrest tests the 1.0-only byte `ps+0x322` (`0x156c3`) and then calls
  `0x37f30`, which draws the other players as APLAYER tiles around the screen centre.
  Nothing writes the byte, so this is dead code.
- **Menus.** The menus function (`0x3a710` / `0x39e50`) differs in many constants.
  1.0 lacks 1.1's hardware-credits page ("THE FOLLOWING COMPANIES WERE COOL …"). Its
  menu save temp file is `d3d.tmp` (1.1: `c:duke3d.tmp`). It was not itemized further.
- The banner reads "v1.0" (`0xc04b5`). The episode and skill names are the same as 1.1,
  including "SCHRAPNEL CITY" at `0xc699e`.
- coords/tics (`0x145e0`) also prints `cheat_phase`. coolgaugetext uses `>> 4` where 1.1
  uses `/ 24`. Both are drawing only.

## 4. Render, DOS and network only (not ledgered one by one)

- **main** (`0x1ea60`): no 3,200,000-byte memory check, no break handler, and no mouse
  init gate.
- **Startup**: calls three extra function pointers when `0xd0a44` is set.
- **gameexit**: calls `closedemowrite` unconditionally, and trims a trailing space from
  the message.
- **comlinehelp**: three fewer help lines.
- **getnames**: no BYTEVERSION byte (F10-004).
- **getpackets / faketimerhandler / fakedomovethings**: 1.0 packet layout and input
  format (F10-001).
- **record / domovethings**: input array offsets only (F10-001).
- **playback**: the pause test is missing from its drawing path.
- **dobonus**: no `volume == 0` test (shareware has one volume); starts music
  `0x12e139` before the E1 ending.
- **displayrooms / animatesprites / view / SetupGameButtons**: drawing, or the
  hitscan cliptype.

## 5. Same in both

These were compared and are the same:
- inittimer, gametext, minitext, gamenumber, ShutDown, check_fta_sounds, badguy,
  badguypic, myos…digitalnumber, operatefta, FTA, binscreen, strget, checksync,
  updatesectorz, the interpolation pair, drawbackground, LocateTheLocator, EGS
  (including the 2048 check), printstr, Logo (960 tics), loadtmb, the demo functions
  (format apart), doorders, cameratext, ceilingglass, vglass
- lotsofglass and lotsofcolourglass. Like tracers, BLOODPOOL and movefta, 1.0 doesn't
  initialize the sector variable it passes to `updatesector` as the start hint (1.1 sets
  it to −1 or to the sprite's sector). `updatesector` falls back to a full search, so the
  result is the same.
- the rest of spawn.
