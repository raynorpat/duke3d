# 1.1 vs 1.3D: CON compiler differences

Compared the 1.1 shareware compiler (`~/Projects/ref/ghidra/sw11.bin`) against the 1.3D
shareware one (`sw13.bin`) and `source/gamedef.c`. The method was a capstone disassembly
of each `parsecommand` jump-table target, diffed handler by handler after masking
addresses, plus the Ghidra decompiles. Everything not listed under "Differences" was
register allocation or code layout only. The 1.3D facts are in
`docs/v13d/notes/1.3d-con-compiler.md`. Addresses below are 1.1 unless marked.

All four keyword helpers reference `keyw[]` (1.1 `0xc6c90`, 1.0 `0xc6788`, 1.3D sw
`0xc7830`).

## Keyword table

`keyw[]` has **94 entries** in 1.1. Every lookup loop runs to 94: `keyword` `0x320a0`
(`cmp 0x5e`), `transword`, `transnum`, and the checks in `define`, `state`, `move`,
`action` and `ai`. Indices 0–64, 66, 67, 70–82, 85–92 are the same strings as 1.3D, so those
opcodes have the same numbers. The rest differ:

| Index | 1.3D | 1.1 | 1.1 compile group (jump table) |
|---|---|---|---|
| 65 | `ifmultiplayer` | `shadeto` | 1 transnum (`0x32ee5`): emits `[65, value]` |
| 68 | `debug` | `ifplayersl` | 1-param if (`0x333fc`) |
| 69 | `endofgame` | `endoflevel` | 1 transnum (`0x32ee5`) |
| 83 | `respawnhitag` | `ifhitedge` | no-param if (`0x33401`) |
| 84 | `tip` | `rise` | no-op, keyword word only (`0x33bc1`) |
| 93 | `lotsofglass` | `debugprint` | no-op (`0x33bc1`) |
| 94–98 | `ifgotweaponce`, `getlastpal`, `pkick`, `mikesnd`, `debug` | — | — |

**So the bytecode of the shipped CONs uses the same numbers for every keyword the two
releases share.** The 1.1 CONs use `shadeto` 9 times (GAME.CON lines 366, 2008, 2009),
`endoflevel` once (line 2328), `ifplayersl` twice (lines 1041, 1190) and `ifawayfromwall`
once (line 1451). They use none of `ifhitedge`, `rise`, `debugprint`, or any keyword that
1.1 lacks.

**`shadeto` does not compile to nothing**, contrary to EDuke32 `8ea1a4d8`. It is in the
same group as `strength` and emits two words, and the interpreter runs it (see the
interpreter notes).

## Differences

1. **EOF or unknown word: no rewind.** Jump-table entry 0 (`tw == -1`) goes to `0x33bc1`
   (`xor dl,dl` and return 0). So does the `ja` for an out-of-range index at `0x32657`.
   1.3D sw goes to `0x346af` (`sub ebx,4` on `scriptptr`). 1.1 keeps no rewind here, which
   is what our tree does outside 1.3D. This reverses C-012. `loadefs` still cuts the buffer
   at fs−2 (`0x33c00`: `end = textptr + fs - 2; *end = 0`).
2. **`definelevelname` (0) leaves one word in the script.** It does `scriptptr -= 4` once
   (`0x3354e`), then reads the volume with `transnum`, rewinds (`0x3356b`), and reads the
   level with `transnum` (`0x33570`) **without rewinding**. There are no further
   `scriptptr` writes up to the next handler at `0x337e9`. 1.3D sw rewinds after both
   (`0x3561f`). Each `definelevelname` therefore adds one word, the level number.
   Other changes:
   - The arrays are indexed `v*9+l`: 9 levels per volume, not 11.
   - Filenames have a stride of 13 (1.3D: 128). The limit is still 14 characters.
   - The partime and designertime math is the same.
   - Both terminators are at `[i-1]`, as in 1.3D.

   1.0 has the same code at `0x32e07`.
3. **Script layout that results (inferred from items 1 and 2):** DEFS.CON emits nothing.
   USER.CON emits `[60, last param]` for `gamestartup`, then 35 level words for its 35
   `definelevelname`s. Both counts are after removing comments, and both are the same in
   1.0 and 1.1. GAME.CON code should start at `script[38]` (`script` = `0x107388`, first
   word `0x10738c`). This has not yet been checked against a DOS save. Task 8 has to
   confirm it word for word, as `con_compile_v13d_*` did for 1.3D.
4. **`gamestartup` (60) reads 22 parameters** (`0x33ac2`, loop bound `cmp ebx,0x16`).
   It rewinds after each one, then does `scriptptr++` at the end, so it emits
   `[60, last param]`, the same as 1.3D. The stores, in order:
   0 `0x130542`, 1 `0x12edf8`, 2 `0x12edec`, 3 `0x12ede8`, 4 `0xc6f6c`, 5 `0xc6f70`,
   6 `0xc6f74`, then seven words at 7–13 (`0x12e29c, 2a4, 290, 2a0, 2b0, 294, 2a8`), then
   14–21 into `0x116204 + 4*j`, which is `max_ammo_amount[1..8]`. The `max_ammo_amount`
   base `0x116238` is the array that `addammo` compares at `0x350a0` case 2. By position
   this is 1.3D's order (C-014) with the last five dropped: `max_ammo_amount[9]`
   (freezer), `camerashitable`, `numfreezebounces` and `freezerhurtowner`.
   - Slot 2 is `max_player_health`: `addphealth` caps against `0x12edec`.
   - Slot 3 is `max_armour`: the multiplayer `resetplayer` stores `0x12ede8` into the
     shield.
   - Slots 4–6 are named by position only.

   There is no gravity parameter. `fall` hardcodes 176 and 29 (`0x35b08`, `0x35b0f`), as
   1.3D does. The shipped USER.CON passes exactly 22 values.
5. **`ai` definition (24): no OR of flags in the third slot.** It takes up to three plain
   `transnum`s and pads to 3 (1.1 decompile `case 0x19`). 1.3D sw ORs every remaining
   flag into slot 3 (`34660.c` `case 0x19`), and so does ours. The shipped 1.0 and 1.1 CONs
   give at most one flag per `ai`, so the bytecode is the same.
6. **Limits.**
   - `definesound` (57) errors when `k > 254`, so there are 255 sounds (1.3D: 348).
   - `definequote` (79) has a limit of 128 (`cmp edi,0x80`; 1.3D: 192).
   - `music` (54) breaks when `i > 8`, so 10 songs per volume, with stride 130 (1.3D: 11
     songs, stride 143).

   No shipped CON reaches any of these limits.
7. **Embedded NUL.** In `keyword`, `transword`, `transnum` and `getlabel`, a NUL found
   while skipping whitespace calls `gameexit(textptr-40)` (`0x14bc0`) when
   `textptr < end` (`0xd2480`). This only happens for a NUL before the main file's cut
   point. Include buffers sit after it in memory.
8. **`loadefs`** (`0x33c00`):
   - It has the "Warnings/Errors found … use the internal defaults" prompts (like ours,
     unlike 1.3D's C-018).
   - It tests the `kopen4load` result against −1.
   - It exits with "Missing .CON file(s)." on a second failure.
   - It reads `loadfromgrouponly` (`0x131581`).
9. **`include`** (55, `0x32d9e`) does not test the open result at all.

## Same as 1.3D

These handlers differ from 1.3D sw only by register allocation and layout:

- `actor`
- `state`, both the definition and the reference
- `ends`, `enda`, `define`, `action`, `move`, `palfrom`
- `{`, `}`, `//`, `/*`
- `else`, which uses `warning++` when there is no `if`, as in C-013
- `betaname`, `definequote` and `definesound` (apart from their limits)
- the 1-transnum, 2-transnum and 5-transnum (`hitradius`) groups
- all the if groups: the keyword, the params, an absolute fail pointer, then the body

As in 1.3D, these top-level keywords emit nothing: `define`, `music`, `include`,
`definesound`, `definequote` and `betaname`.
