# player.c: 1.0 shareware compared with 1.1 shareware

Scope: the player.c functions in `1.1-player.md`, using the `1.0-game.md` method. fmatch
pairs all 22 functions, from setpal (`0x3f1e0` / `0x3e880`) to processinput (`0x44cf0` /
`0x441e0`). Five are identical after normalization. Player fields use the 1.0 map in
`reference.md` ("player_struct (1.0)"), and weapons use the 1.1 numbering, which 1.0
shares (same projectile table at `0xc6a4c`). Ledger rows are `G10-Lnn`.

### getinput (`0x43f20` / `0x43520`)

1.0 builds the 1.0 input record (F10-001):
- **Keyboard turning:** `avel ±3` for the first 16 tics (`turnheldtime < 17`), then ±6
  (±12 when running). 1.1 uses ±10 for the first 15 tics, then ±30/±60.
- **Clamps:** `avel` ±108 (1.1 ±127). `fvel` and `svel` ±90 (the same).
- **Mouse:** `avel = mousex >> 8`. 1.1 scales mousex by `/32` and adds the vertical
  `horz`.
- **Running:** the Run key or the per-player `ps.auto_run` (`0x34c`, `0x4390a`).
- **Bits:** no bit 12 (Steroids), no bit 23 (aim mode), no `horz`. Bit 17 is AutoRun.
- Moving clears `cheat_phase`.

Input only, so it is rowed n/a, as G11-L98 was. A 1.0 build that records demos needs it.

## Same in both

setpal, incur_damage, quickkill, forceplayerangle, displayloogie and the other display
functions (apart from reading the 16-bit `avel`), and the rest of shoot, doincrements and
processinput. As far as the instruction diff shows, that includes G11-L07, L09, L10,
L12, L13, L17, L18, L21, L22 and L24–L31. L16's bit-12 look code is there too, but 1.0
getinput never sets bit 12. G11-L05, L15, L16 (friction) and L20 differ as above. L32's
player FLAMETHROWER path is reachable in 1.0, because the fire start accepts weapon 7.
