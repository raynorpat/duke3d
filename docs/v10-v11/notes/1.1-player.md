# player.c: 1.1 shareware compared with 1.3D shareware

Scope: everything `docs/v13d/notes/1.3d-player.md` covers, from `sw11.bin` against
`sw13.bin`. Addresses are flat image addresses (base `0x10000`). "1.3D" means the 1.3D
shareware EXE, whose behavior this tree already has under `DUKE3D_GAMEVER < GAMEVER_14`.
Ledger rows are `G11-Lnn`, after the 1.3D `G13-Lnn` rows. Player fields are named from the
1.1 `player_struct` map in `docs/v10-v11/reference.md` ("player_struct (1.1)"). Weapon
numbers follow the 1.1 `DEFS.CON`:
- 0–6 as 1.3D: KNEE, PISTOL, SHOTGUN, CHAINGUN, RPG, HANDBOMB, SHRINKER
- 7 FLAMETHROWER
- 8 TRIPBOMB
- 9 HANDREMOTE

## Method

1. **Pairing.** fmatch (`fmap11.txt`) pairs the module in source order, from setpal to
   processinput.
2. **Token diff.** Each pair was disassembled and normalized: registers dropped, calls
   mapped through fmatch, globals mapped by an address vote over all aligned
   instructions, and `ps` offsets mapped through the 1.1 field map. The streams were then
   diffed. Every hunk that was not code generation was read in the disassembly at the
   address given.
3. **Decompiles.** processinput, shoot, aim, doincrements and getinput were also read
   side by side with this tree's source, using decompiles annotated with the field names.

### Hitscan weapons (shoot SHOTSPARK1, SHOTGUN, CHAINGUN)

- **Player aim:** no GREENSLIME/ROTATEGUN `-8<<8` aim offset.
- **SHOTGUN spread:** `sa += 24 - krand()%48`, `zvel += 256 - (krand()&511)`. 1.3D uses
  `16 - (krand()&31)` and `128 - (krand()&255)` (`0x40523`–`0x40593`).
- **Enemies:** no BOSS1 special case. Every enemy uses `sa += 32 - (krand()&63)` after the
  zvel krand.
- **Tracers:** fire when `(krand()&7) == 0` in water, with count 5. 1.3D uses `&15` and
  `8 - (multimode>>1)` (`0x406af`–`0x406eb`; 1.3D `0x432e4`).
- **Player spark that hits a parallaxed ceiling:** returns without hiding the spark (1.3D
  sets its size to 0).
- **Player hits a sprite:** DIPSWITCH and DIPSWITCH2 (162–165) only trigger hitswitch; there
  is no DIPSWITCH3 or HANDSWITCH.
- **Player hits a wall:**
  - The dipswitch list is the same short one.
  - When a BULLETHOLE spawns, a krand is drawn, and `< 2` plays PISTOL_RICOCHET on it.
  - After checkhitwall, `(krand()&255) < 16` plays PISTOL_RICOCHET with xyzsound and
    returns.
- **krand count:** No other path draws the final ricochet krand. 1.3D draws
  `(krand()&255) < 4` once at the end of every path, enemy shots included. This changes
  the krand count per shot.

## 4. Render, UI and input

- **setpal:**
  - no FLOORSLIME-ceiling slime palette
  - `heat_on` selects the palette at `0xd2108`
  - sets `restorepalette` (`0xd2451`)
- **displaymasks:** grows to 1073 bytes and draws the space-suit mask from `spacesuit_on`
  (`0x41f24`).
- **displayweapon** (`0x42750`) has the flamethrower. The other draw functions were not
  diffed.
- **displayrooms:** skips view interpolation while `on_sector_effector` is set
  (`0x165f6`).
- **Frag quotes:** processinput's death code always writes quote 115 and quote 116, and
  shows both (FTA), with no `screenpeek` test.
- **getinput:**
  - only `Weapon_1`–`Weapon_6` set weapon bits, as values 1–6
  - there are no next/previous weapon keys
  - bit 12 is gamefunc 48 (Steroids), the key processinput reads as above
  - aim mode flips on the Mouse_Aiming key edge, with quotes 44/45
  - mouse pitch is `info.dz / 186`
  - speed doubles with auto-run or the run key
  - these change only what a live player records, not playback
- **Audio:**
  - underwater sound
  - timebeforeexit has no `clearsoundlocks` (`0x4533e` area)
  - no DUKE_LONGTERM_PAIN in doincrements' air loss
  - the `ud.coop != 0` (not `== 1`) gates on doincrements' sounds
  - the ricochets above
