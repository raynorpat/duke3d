# game.c: 1.1 shareware compared with 1.3D shareware

Scope: everything `docs/v13d/notes/1.3d-game.md` covers. Each function in `sw11.bin` is
compared with its counterpart in `sw13.bin`, the 1.3D shareware build that our 1.3D-sw
configuration matches. Addresses are flat image addresses (base `0x10000`). "1.3D" below
means the 1.3D shareware EXE unless it says "full". Ledger rows are `G11-Gnn`.

## Method

1. **Pairing.** fmatch (`fmap11.txt`) pairs only 21 of the 78 game functions, so the rest
   were paired by position, size, callees and strings. Five 1.3D game functions have no
   1.1 counterpart, and 1.1 moves three (Startup, ShutDown and checksync) to other places
   in the file.
2. **spawn.** A walker follows the Watcom compare tree for every picnum from 0 to 8191 in
   both EXEs (1.1 tree head `0x17667`, 1.3D `0x18142`). Every picnum is either a case
   target or a bare return (`mov eax,edi; add esp,0x28; pop…; ret`). Neither spawn has a
   default block. Case bodies were compared as control-flow-ordered, normalized
   instruction traces: sprite, hittype, sector and ps operands become field offsets, other
   globals are masked and calls are mapped through fmatch. Every non-empty diff was read
   in the raw disassembly.
3. **Other functions.** These were compared by decompile, with the same trace diff for
   the glass functions, Logo, prelevel and the SE cases.
4. **Shipped-map impact.** A scan of the six 1.1 maps in `DUKE3D.GRP` (sprite picnum,
   pal and SE lotag counts) shows which spawn differences the shipped levels reach.

1.1 tile names below that are not in `names.h` come from the 1.1 `DEFS.CON`: 45
`FUELCAN`, 58 `BODYSUIT`, 1425 `DUMMYDUKE` and 1430 `BIGDUMMYDUKE`.

### EGS (`0x16f80`)

Same field writes as 1.3D. 1.1 adds `if (i < 0 || i >= 2048) gameexit(...)` right after
`insertsprite` (`0x16f99`–`0x16fa4`; format string at `0xc011c`). So spawning a sprite
whose index is 2048 or higher ends the game. The 1.1 save format keeps only
`hittype[2048]` (reference.md, "Save file").

## 6. Title, menus, bonus screens and names

- **Episode names** (`0xc6e68`, 33-byte stride; neither release's CON defines them): 1.1
  "L.A. MELTDOWN", "LUNAR APOCALYPSE", **"SCHRAPNEL CITY"**. 1.3D has "SHRAPNEL CITY"
  (`0xc7a5e`). The skill names (`0xc6ecb`) are the same.
- **Logo (`0x1e8b0`)**: same tiles (DREALMS 2492, BETASCREEN 2493, DUKENUKEM/THREEDEE zoom
  with sound 14, then sound 213) and no `logo.anm`, as in 1.3D sw. The 3D Realms screen
  waits up to 960 tics (`0x3c0`; 1.3D 840). Both start the environment music
  (1.1 `0x12ed88`); 1.3D stops the current song first.
- **Startup (`0x23450`)**: prints "IT IS NOW TIME TO UPGRADE TO THE COMPLETE VERSION!!!"
  when the config counter `0x130566` exceeds 49. main loads the CONs after Startup and
  loadtmb. The memory check needs 3,200,000 bytes (1.3D 2,800,000).
- **doorders (`0x214a0`)**: the same four ORDERING screens (`0xcc6`–`0xcc9`), called from
  main at the end of the episode (section 4).
- **dobonus (`0x21710`)**: the episode 1 ending (tiles `0xcbc`, `0xcc4`, `0xcdc`) plays
  when `!bonusonly && volume == 0 && numplayers < 2 && level_number == 5 && from_bonus ==
  0`. 1.3D uses `ud.eog` and `!from_bonus`, and skips the ending animation when
  `lockout` is set. 1.1 has no episode 2 or 3 ending (`cineov2/3.anm`, `RADLOGO.ANM`,
  `DUKETEAM.ANM`). The bonus screen strings and layout are the same.
- **nonsharedkeys (`0x1d4f0`)**: no Shift-F5 music change and no "PLAYING …" quote. The
  quick-save temp file is `d3d.tmp` (1.3D `duke3d.tmp`).
- **resetplayerstats and enterlevel keep the third-person view** across levels (premap
  notes).
- **Interpolation**: 1.1 has its own sector interpolation (`0x15cc0`/`0x15d50`, count
  `0x12ed74`). It extrapolates along a stored velocity toward a goal, and neither
  domovethings nor spawn set it up the 1.3D way. This is render only.
