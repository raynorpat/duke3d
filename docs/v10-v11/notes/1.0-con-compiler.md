# 1.0 vs 1.1: CON compiler differences

I compared the 1.0 compiler (`sw10.bin`) handler by handler against 1.1. Addresses are
listed in `1.1-con-compiler.md`. Apart from what is listed here, the handlers match 1.1
after masking addresses and register choice. That includes the no-rewind EOF path
(table entry 0 → `0x33407`) and the `definelevelname` leftover word (`0x32e07`).

## Differences

1. **`keyw[]` has 93 entries** (`0xc6788`). Lookups loop to 93 (`keyword` `0x31980`:
   `cmp 0x5d`), and the jump table at `0x31d2c` has 94 entries (`tw+1`). Indices 0–89 and
   91–92 match 1.1. **Index 90 is `debugprint`** (in 1.1 that slot holds
   `ifawayfromwall`, and 1.1 puts `debugprint` at 93). 1.0 has no `ifawayfromwall`. The
   1.0 CONs use neither keyword. `debugprint` is in the no-op group (`0x33407`).
2. **`gamestartup` reads 13 parameters** (`0x33384`, `cmp ebx,0xd`). The stores, in
   order: 0 `0x130e9b`, 1 `0x12e7e4`, 2 `0x12e7d8`, 3 `0x12e7d4`, 4 `0xc6a60`, then 5–12
   into `0x1129f8 + 4*j`. `max_ammo_amount` is at `0x112a08`, the base that `addammo`
   compares, so slots 5–12 are `max_ammo_amount[1..8]`.

   By position this is 1.1's first five values (`const_visibility`, `impact_damage`,
   `max_player_health`, `max_armour`, `respawnactortime`) followed by the 8 ammo maxima.
   There is no item respawn time, no `dukefriction` and no blast radii, which agrees with
   EDuke32 `8ea1a4d8`. It still emits `[60, last param]`. The shipped 1.0 USER.CON passes
   exactly 13 values.
3. **`loadefs`** (`0x33450`): only the y/N prompt loop differs. 1.0 loops until it gets y/Y, and exits on n, N, 0x01 or
   0x1b (ESC). The fs−2 cut is the same (`end = textptr + fs - 2`).

## Script layout

This is the same arithmetic as 1.1: USER.CON emits 2 words for `gamestartup` and 35 for
its 35 `definelevelname`s, so GAME.CON code should start at `script[38]` (`script` =
`0x102f08`). It is not yet checked against a DOS save.
