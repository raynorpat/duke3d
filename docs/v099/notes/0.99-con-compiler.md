# 0.99 vs 1.0: CON compiler differences

I compared the beta's compiler (`beta099.bin`) against 1.0's (`sw10.bin`,
`docs/v10-v11/notes/1.0-con-compiler.md`) function by function. Method:
- `keyw[]` dumped from the flat image and diffed string by string.
- Both `parsecommand` jump tables (94 entries each) dumped, and checked to be a bijection
  between 1.0 and beta targets, so every keyword is in the same compile group.
- Each handler disassembled with capstone from its table target to the next, diffed after
  masking addresses and registers, and its immediates compared. Every handler whose
  instructions or constants differed was read side by side in the disassembly and the
  Ghidra decompile.

Ledger rows: `C099-001` to `C099-008` and `C099-030`.

## Function map

| Function | 0.99 | 1.0 | Result |
|---|---|---|---|
| `getlabel` | `0x2e0f0` | `0x318d0` | same (the beta inlines `ispecial`) |
| `keyword` | `0x2e1c0` | `0x31980` | same, 93 entries (`cmp 0x174` on a byte offset) |
| `transword` | `0x2e250` | `0x31a10` | same |
| `transnum` | `0x2e390` | `0x31b30` | same |
| `parsecommand` | `0x2e750` | `0x31ee0` | differs (below) |
| jump table (`tw+1`) | `0x2e5a4`, 94 entries | `0x31d2c`, 94 entries | same grouping |
| compile loop | `0x2fc20` | `0x33420` | same |
| `loadefs` | `0x2fc50` | `0x33450` | differs (below) |

Globals: `textptr` `0x108568`, `scriptptr` `0x108564`, `parsing_actor` `0x10855c`,
`parsing_state` `0xb0586`, `num_squigilly_brackets` `0xb0580`, `checking_ifelse`

`labelcode` `0x108550`, `error` `0x10aef8`, `warning` `0x10aef7`, end-of-file pointer
`0xb0574`, `script` `0xe1018` (first word `0xe101c`), `actorscrptr` `0xec808`.

## Keyword table

`keyw[]` (`0xa5868`) has **93 entries**, as in 1.0. Every lookup stops at 93
(`keyword`, `transword`, `transnum`, and the label checks in `define`, `state`, `move`,
`action` and `ai`). **Only index 69 differs: the beta has `activate` where 1.0 has
`endoflevel`.** Every other string is at the same index, so all shared keywords keep
their opcode numbers. Index 90 is `debugprint`, as in 1.0. There is no `ifawayfromwall`.

Index 69 is in the same compile group as in 1.0 (the one-`transnum` group, target
`0x2f02d`), so `activate <value>` emits `[69, value]`.

Keyword uses in the beta CONs, after comments are removed: `activate` once, `shadeto`
8 times, `palfrom` 20 times (at most 3 values each), `definelevelname` 35 times and
`gamestartup` once. `debugprint` and `endoflevel` are not used.

## Hypotheses (EDuke32)

- **`activate` (`8b9f4345`).** It compiles to `[69, value]` and nothing more: the handler
  at `0x2f02d` calls `transnum` and returns. It doesn't rewrite its own slot. At run time
  it calls `operateactivators(value)` (see the interpreter notes). EDuke32's slot rewrite
  is its own mechanism. The EXE has nothing like it.
- **`shadeto` (`8ea1a4d8`).** It does **not** compile to nothing. It is in the same
  one-`transnum` group (`0x2f02d`) and emits `[65, value]`, as in 1.0 and 1.1.
- **`definelevelname` with one time (`ed97e5d0`).** Confirmed (`0x2f692`). See item 1.
- **Startup parameters (`8ea1a4d8`).** `gamestartup` reads **13** values (`0x2fb83`,
  `cmp edx,0xd`), in 1.0's order. Its inner jump table (`0x2e71c`) stores them to
  `0xf0ccc` (`const_visibility`), `0x10857c` (`impact_damage`), `0x108bc0`
  (`max_player_health`, the `addphealth` cap), `0x108578` (`max_armour`, the multiplayer
  `resetplayer` shield), `0xa5b54` (`respawnactortime`), then 5–12 into
  `0xf0e80 + 4*j`, which is `max_ammo_amount[1..8]` (`addammo` compares against
  `0xf0e90`). It emits `[60, last value]`. The beta USER.CON passes exactly 13 values.

## Differences

1. **`definelevelname` (0) reads one time** (`0x2f692`). After the file name (still
   stride 13, limit 14, 9 levels per volume) it reads one `mm:ss` value into `0xb1be0 +
   4*(v*9+l)`, skips spaces and reads the level name (32 characters, upper-cased, into
   `0x108040 + 33*(v*9+l)`). 1.0 reads two times, into `0xd3ad0` (`partime`) and
   `0xd39f0` (`designertime`). Only `dobonus` (`0x2c010`) reads `0xb1bdc + 4*(v*9+l)`,
   and it prints that value after "Our Best time:", under "Your Time:". The beta has no
   "Par time" or "3D Realms' Time" strings. The handler still leaves one word, the level
   number, in the script, as in 1.0.
2. **`palfrom` (14) takes up to 3 values** (`0x2eb8e`): `transnum` while the next word is
   not a keyword and fewer than 3 have been read, then zero padding to 3 (`cmp edx,3`).
   So it always emits 4 words. 1.0 takes up to 4 and emits 5 (`0x3230f`, `cmp ebx,4`).
3. **ESC aborts the compile.** `parsecommand` starts by testing the ESC key-down byte
   (`0x21a8a1`, the byte getinput puts in bit 31) and calls `gameexit(" ")` if it is set
   (`0x2e77c`–`0x2e78a`). 1.0 has no such test.
4. **`loadefs` prompts** (`0x2fc50`):
   - Warnings, no errors, a GRP open and not already loading from it: "Warnings in %s
     file. Use defaults (Y/N)?". `y`/`Y` sets `loadfromgrouponly` and the caller
     recompiles from the GRP. `n`/`N` keeps the compiled script. Other keys are ignored.
   - Errors: if already loading from the GRP, `gameexit("Error in %s.")`. If there is no
     GRP (`0x1084fc == -1`), `gameexit("")` (`0x2fe81`). Otherwise "Errors in %s file.
     Use defaults (Y/N)?": `y`/`Y` reloads from the GRP, any other key exits.
   - 1.0 exits on `n`, `N`, `0x01` or ESC at the warnings prompt, and does nothing when
     there are errors and no GRP. Our `loadefs` keeps going on any key but `y` at the
     warnings prompt, and keeps going with errors and no GRP.

## Same as 1.0

Apart from the items above, the handlers match 1.0 after masking addresses and registers:
- `actor`, `state`, `ends`, `enda`, `define`, `action` (5 values), `ai` (3 plain values,
  no OR), `move` (the OR of flags inside an actor), `{`, `}`, `//`, `/*`, `else`
- `music` (10 songs per volume, stride 130), `include`, `definesound` (255),
  `definequote` (128), `betaname`
- the one-, two- and five-`transnum` groups, and all the `if` groups
- EOF, or an unknown word, returns without rewinding (table entry 0 and the `ja` both go
  to `0x2fc0f`)
- `loadefs` cuts the buffer at `fs-2` (`0x2fcea`–`0x2fcf7`)

## Script layout

DEFS.CON emits nothing. USER.CON emits `[60, last value]` and one level word for each of
its 35 `definelevelname`s. `scriptptr` starts at `0xe101c` (`script[1]`), so GAME.CON
code should start at `script[38]`, as in 1.0. This has not been checked against a DOS
save yet.
