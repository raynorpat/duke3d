# actors.c: 0.99 beta compared with 1.0 shareware

Research snapshot: draft ledger statuses below describe the initial audit.
The current implementation status is in the [authoritative plan](../../superpowers/plans/2026-10-21-v099-variant.md#differences-ledger).

Scope: the actors.c functions of `docs/v10-v11/notes/1.0-actors.md` (28 in `sw10.bin`
`0x23000`–`0x3133f`), against the beta's actor block at the start of the code object
(`beta099.bin` `0x10030`–`0x1c4f5`). Every difference is stated against OUR 1.0 code, that
is the `DUKE3D_GAMEVER < GAMEVER_11` / `< GAMEVER_13D` paths of `source/actors.c`. A port
would add `< GAMEVER_10` branches inside those paths. Ledger rows will be `G099-nnn`.

## Method

1. **Pairing.** fmatch pairs only `ssp` (exact). The rest were paired by source order (the
   beta keeps 1.0's order, from `ceilingspace` through `moveexplosions`), by the
   reference.md call-position rows and by call graphs. Callees were mapped by voting on
   call positions in aligned code (`scratch/t5-actors/callmap.txt`: `0x1dca0` badguy,
   `0x204d0` FTA, `0x22570` EGS, `0x228f0` spawn, `0x2df20` makeitfall, `0x2dc30`
   getglobalz, `0x3b020` shoot, `0x3ab60` hitasprite, `0x45b80` callsound, `0x4ce00`
   spritesound, `0x22520` LocateTheLocator, `0x45fa0`/`0x45f70` dist/ldist, `0x45fd0`
   findplayer, `0x45f20` checkcursectnums, `0x5c1c1` hitscan, `0x6c960` FindDistance2D).
2. **Instruction diff** (`scratch/t5-actors/cmp.py`). Both sides are disassembled with
   capstone. Constants of `0x100` and above are masked for the alignment, then a constant
   map (beta → 1.0) is voted from the aligned instructions of all 30 pairs plus the 210
   fmatch "order" pairs (`cmap.txt`, 412 entries). The masked operands map one to one
   except for the expected small struct offsets (`ps` and `sprite` fields that share a
   value). The residual diff is clean for the small functions. For the movers, which the
   beta compiles with `imul` where 1.0 uses `lea` chains, a second tool (`sig.py`) diffs
   only the call and immediate-constant sequence; every hit was then read in the Ghidra
   decompile (`dc_beta099/`, plus 15 new ones in `scratch/t5-actors/dc99`) and in the
   disassembly, against our source preprocessed for 1.0 with `unifdef`
   (`scratch/t5-actors/actors10.c`).
3. Every structural claim below was checked in the disassembly; the address after a claim
   is where.

## player_struct and hittype

`ps[]` is `0xf0f38`, stride `0x33f`. The hittype layout is 1.0's (71 bytes; `temp_data[0]`
at `+0x2f`, `owner` `+7`, `actorstayput` `+0xd`, `floorz`/`ceilingz` `+0x13`/`+0x17`,
`bposx..z` `+0x23`..`+0x2b`). Names are this tree's.

The field map (0.99 offsets against 1.0) is in `0.99-player.md`, "player_struct".

Globals used: `god` `0xf0988`, `ud.recstat` `0xf0d0c`, `ud.camerasprite` `0xf0cc6`,
`ud.respawn_monsters` `0xf0d08`, `earthquaketime` `0x10aef1`, `global_random` `0x109ff2`,
`screenpeek` `0x109fee`, `myconnectindex` `0x21a3de`, `connecthead` `0x21a3d8`,
`max_player_health` `0x108bc0`, `impact_damage` `0x10857c`, `respawnactortime` `0xa5b54`
(1.0 `0xc6a60`), `max_ammo_amount` `0xf0e90`, `camsprite` `0x109fec`.

## Differences

Each paragraph is "0.99 does X; our 1.0 code does Y". **[sync]** marks a change to game
state that a demo would see; **[krand]** marks a change in the number or order of krand
calls.

### Small functions

- **addammo / addweapon / checkavailweapon:** all three end with `ps+0x322 = 1` (a word),
  as C099-013's `addphealth`/`addinventory` do. Nothing in the actor code reads it.
- **addweapon** (`0x101b0`): the no-sound list is `KNEE, HANDBOMB, TRIPBOMB` only, so
  `HANDREMOTE_WEAPON` (9) plays `SELECT_WEAPON`. 1.0 also skips 9. Audio only.
- **checkavailweapon** (`0x10210`): the beta uses the registered (non-`VOLUMEONE`) lists.
  `check_shoot` for weapons 0–4, 6, 7; `check_bombs` for 5, 8, 9. The shoot scans accept
  1, 2, 3, 6, 7 (`i<4 || (5<i<8)`); both bomb scans accept 5 and 8 (`4<i && (i<6 || i==8)`).
  1.0 (= our `VOLUMEONE` path): shoot set 0–4, bomb set 5, 9; shoot scans 1–3; downward
  bomb scan 5 only. Port: `< GAMEVER_10` lists in the `< GAMEVER_14` checkavailweapon.
- **checkavailinven:** no counterpart. No beta function sets `inven_icon` in 1…8 order.
  The 1.0 callers are player.c (`0x43c40`, processinput `0x441e0`, `0x4fb10`); the player
  comparison decides what replaces them.
- **lotsofmoney** (`0x10fd0`) **[krand]**: no `sprite[j].cstat = TRAND&12`. Two krands per
  bill (angle, then z), not three.

### hitradius (`0x104e0`) [sync]

The ceiling and wall passes and the statlist `{0,1,6,10,12,2,5}` (`0x10010`) are 1.0's.
In the sprite pass:
1. **No cansee for badguys.** The `x == 0 || x >= 5 || AFLAMABLE` branch is
   `if((s->picnum != SHRINKSPARK || (sj->cstat&257)) && dist(s,sj) < r) checkhitsprite(j,i);`
   (`0x107fa` dist → `0x10813` checkhitsprite). There is no `q` and no `badguy && !cansee`
   test (ours G10-A02's `q = zvel<0 ? 0x2000 : -0xc00`).
2. **Target list** (`0x10830`–`0x10855`): `sj->extra >= 0 && sj != s && (TRIPBOMB ||
   badguy || (cstat&257) || DUKELYINGDEAD)`. No QUEBALL or STRIPEBALL.
3. **Push exclusion** (`0x10a5c`): `RECON, BOSS1, BOSS2`. No ROTATEGUN.
4. **FEM checkhitsprite** (`0x10aad`): `FEM1, FEM2, FEM3`. No PODFEM1 or FEM4.
5. No QUEBALL/STRIPEBALL checkhitsprite after the damage branch (1.0's G10-A02 row).

The three damage krands, SHRINKSPARK/MORTER skips, APLAYER `PHEIGHT` offset, `hittype`
picnum choice and owner hand-off are 1.0's.

### movesprite (`0x10b60`) [sync] [krand]

Badguy path, replacing ours:
```c
cd = (picnum == BOSS1 || picnum == BOSS2) ? 512 : 192;          // 0x10cd0; 1.0: 1024
retval = clipmove(..., cd, 4<<8, 4<<8, cliptype);
if (dasectnum >= 0 && sprite[spritenum].zvel >= 1024 &&            // 0x10d32
    (sector[dasectnum].lotag == 1 ||                               // 0x10d52
     (hittype[spritenum].actorstayput >= 0 && hittype[spritenum].actorstayput != dasectnum)))
{
    if (sprite[spritenum].extra <= 0) hittype[spritenum].actorstayput = -1;
    else if (sprite[spritenum].picnum != OCTABRAIN)                 // 0x10dc3
    {   x = oldx; y = oldy; setsprite(spritenum,oldx,oldy,z); return 16384+dasectnum; }
}
// no "(retval&49152) >= 32768 && cgg == 0 -> ang += 768"
```
The `zvel >= 1024` gate is what the code tests (`movsx eax,[sprite+0x24]; cmp eax,0x400;
jl`). There is no `ang = TRAND&2047` (1.0 `0x23e3c`): one krand fewer on every stayput
bounce. The early statnum-5 path, the non-badguy clip (8/128) and the z part are 1.0's.

### ifhitbyweapon (`0x115e0`) [sync]

Player branch, replacing ours:
```c
npc->extra -= hittype[sn].extra;  if (npc->extra < 0) npc->extra = 0;
ps[p].posxv += hittype[sn].extra*sintable[(ang+512)&2047]<<1;   // always <<1
ps[p].posyv += hittype[sn].extra*sintable[ang&2047]<<1;
```
No god test (`0xf0988` is never read here), no `j`/`wackedbyactor`/`frag_ps`/owner code,
and no `<<2` case for explosions. The non-player branch is 1.0's (SHRINKSPARK `< 40`,
RECON owner test, THROWFLAME shade).

### moveplayers (`0x11aa0`)

1. **Holoduke** (`0x11d90`–`0x11dc3`): `xrepeat` grows to 48, `yrepeat` to 44 (1.0 42/36).
2. **god** (`0x11bf4`): `extra = max_player_health; jetpack_amount = 1599`. No
   `cstat = 257`. Cheat-only (no cheats while recording, reference.md).
3. **Alive** (`0x11c10`): no `hittype[i].owner = i`.
4. **Dead** (`0x11cc2`–`0x11d2a`) [sync]: turns toward `hittype[i].owner` (there is no
   `wackedbyactor`):
   `j = hittype[i].owner; if(j >= 0 && sprite[j].statnum < MAXSTATUS && j != i) p->ang += getincangle(p->ang, getangle(sprite[j].x-p->posx, sprite[j].y-p->posy))>>1;`
   with **no `&= 2047`** and no G10-A05 distance test.
5. Multiplayer kick: `otherx < 844`, `knee_incs == 10` calls quickkill without `frag_ps`;
   `knee_incs == 0` also sets `holster_weapon = 1`. Multiplayer only.

### movefx (`0x11e90`)

- RESPAWN (`0x11ed8`–`0x11f17`): the timer is `shade`, not `extra`: spawn at
  `shade == 66`, count up past 53 (G099-015).
- Reverb (`0x11f46`–`0x11fa9`): inside `hitag`, `FX_SetReverb((lotag-1000)*x/(hitag+1))`
  and `T1 = 1` every tic (no `T1 == 0` test); outside with `T1 == 1`, `FX_SetReverb(0)`
  only (no `FX_SetReverbDelay`).
- Ambience: no `floorz != ceilingz` test, and no `soundm&16` random-sound block (so no
  `T5` countdown, 1.0's G10-A97).

### movestandables (`0x12490`)

1. **AFLAMABLE burn** (`0x12bc1`, `0x12c02`): `xrepeat -= TRAND&1`, `yrepeat -= TRAND&1`
   (1.0 `&7`). Same two krands. [sync]
2. **WATERFOUNTAIN** (`0x12acf`): when `t[0] >= 20`, `sprite[s->owner].extra++` before the
   findplayer. Who owns the fountain is checksectors' business (player module). [sync]
3. **TRIPBOMB:**
   - findplayer runs every tic, not only while `t[0] < 32` (no effect).
   - `t[0] == 32`: no `z -= 3<<8` / `z += 3<<8` around the laser trace.
   - `t[0] == 33` (`0x13002`–`0x130ca`): no sprite move and no hitasprite. Instead:
     `t[1]++; hitscan(x+(sintable[(ang+512)&2047]>>13), y+(sintable[ang&2047]>>13), z-1024, sectnum, sintable[(ang+512)&2047], sintable[ang&2047], 0, ...);`
     then `if((hittype[i].lastvx>>7) != (FindDistance2D(hitx-x,hity-y)>>7)) { t[2] = 13; spritesound(LASERTRIP_ARMING,i); }`.
     It uses `s->ang`, not `T6`.
4. **No OOZFILTER anywhere:** the CRACK and FIREEXT hit lists, the hitag shade loops,
   the SEENINE family (`SEENINE, SEENINEDEAD, SEENINEDEAD+1`) and MASTERSWITCH's
   shade -31 all test SEENINE only.
5. **No TRASH case** **[krand]**: a statnum-6 TRASH does nothing (1.0 draws one krand per
   tic, two while slow).
6. **BOLT1** **[krand]**: no `SHORT_CIRCUIT` test, so no `TRAND&1` when the picnum reaches
   `BOLT1+1`.
7. **WATERDRIP** (`0x13a36`–`0x13a91`) **[krand]**, replacing ours:
   ```c
   if (t[1]) t[1]--; else makeitfall(i);
   if (s->zvel == 0) {
       if (sprite[s->owner].picnum != WATERDRIP) KILLIT(i);
       s->z = t[0];
       t[1] = 16+(TRAND&15);
   }
   goto BOLT;
   ```
   No ssp, `xvel` decay, cstat toggles, `bposz` or SOMETHING_DRIPPING. While waiting,
   `zvel` stays 0, so the reset (and its krand) runs **every tic**. A map drip with
   `zvel 0` never drips and draws one krand per tic for the whole level.
8. **VIEWSCREEN** only (no VIEWSCREEN2 case), and `loadtile(VIEWSCREEN)`. Display.
9. TOUCHPLATE calls the one-argument operateactivators (C099-009); the rest is ours.

CRANE, FIREEXT debris, SEENINE (apart from item 4), MASTERSWITCH, DOORSHOCK,
CANWITHSOMETHING and the `execute` list are 1.0's. The `execute` list is WATERBUBBLEMAKER,
EGG, WOODENHORSE, TOILETWATER, HORSEONSIDE, RUBBERCAN, NUKEBARREL*, EXPLODINGBARREL,
FIREBARREL and FLOORFLAME.

### moveweapons (`0x13e00`)

The same as our `< GAMEVER_13D` function with 1.0's G10-A08 forms, except that
SHRINKSPARK's hit has no `spritesound(SHRINKER_HIT)` (`0x14956`). Audio only. SPIT adds 64
to `zvel` as a constant, which equals `gc-112` with the stock `gc`.

### movetransports (`0x14ad0`) [sync]

1. `if(T5 && T1 > 0) T1--;`: it only counts down on floor transporters (`0x14b20`).
2. Player (statnum 10):
   - With `owner == -1` it goes to the sprite path, not skipped (`0x14ba0`).
   - Floor teleport (`sectlotag == 0 && onfloorz && jetpack_on == 0`, **no on_ground**,
     `0x14be3`): spawn beam and TELEPORTER; for players in the destination,
     `hittype[ps[k].i].owner = ps[p].i; sprite[ps[k].i].extra = 0`; `ang = OW.ang`;
     `T1 = 26; hittype[OW].t[0] = 26; transporter_hold = 2` (1.0 13/13/13).
     `pos = opos = OW.xy, z-PHEIGHT`; `updatesector(OW.x, OW.y, &cursectnum)` and **no
     changespritesect** of the player sprite; spawn beam at OW, TELEPORTER on OW.
   - Non-floor: warp when `klabs(SZ-posz) < 4096` (1.0 6144); `posz = OW.z -/+ 4096`
     (1.0 6144); up only on `jetpack_on && (bits&1)` (no `jetpack_on < 11`).
   - Water: `FX_StopAllSounds` without `clearsoundlocks`. The palette is
     `waterpal` when the destination sprite's `pal == 8`, else setpal (display).
3. Sprites:
   - `ll = klabs(zvel); if(ll == 0) next;`: **zero-`zvel` sprites never warp**
     (`0x1517e`).
   - Lotag 0 with `onfloorz && T1 > 0`: skip this sprite and continue (1.0 `T1++; goto BOLT`).
   - Skip list (`0x15271`): BULLETHOLE, TRANSPORTERBEAM, WATERSPLASH2, TRANSPORTERSTAR,
     SHELL, SHOTGUNSHELL, TRIPBOMB. **No BURNING, FIRE, BURNING2, FIRE2.**
   - Lotag 0 `onfloorz`: `T1 = 4` and `hittype[OW].t[0] = 4` (1.0 13). When
     `checkcursectnums` finds a player, the sprite is still changespritesect'd to the
     destination **without moving**.
   - No `bposx/y/z` stores.
4. **PLAYERONWATER bug** (`0x152a7`): in a lotag-2 transporter it does
   `sprite[j].statnum &= 0x8000` (ours `cstat &= 32767`). That zeroes `statnum` without
   changespritestat, and a later deletesprite would unlink from the wrong list. Fixed, not
   copied: no store (G099-066, rulings).

### moveeffectors (`0x15630`)

There is no `fricxv = fricyv = 0`; the beta's conveyors move players directly.

- **SE 11 swing door** (`0x16cd9`–`0x16e35`) [sync]: no `t[5]` delay. A blocking player is
  tested with `clipinsidebox(...,128)` (1.0 144, `0x16d7d`), and blocking just ends the tic
  (`goto BOLT`, no reversal). On finishing, `callsound(sect,i)` sits between ms and
  setsprite.
- **SE 24/34 conveyor** (`0x17da6`) [sync]: for every player with
  `cursectnum == s->sectnum && on_ground && klabs(posz-hittype[ps.i].floorz) < PHEIGHT+(8<<8)`,
  do `posx += x>>1; posy += l>>1; opos = pos; updatesector(posx,posy,&cursectnum);
  setsprite(ps.i, its own x,y,z)`, and for `myconnectindex` also adjust the prediction
  (`0x107a60/64`). Not `fricxv/fricyv`. No sprite `bposx/bposy`.
- **SE 26** (`0x18378`) [sync]: for every player on it, `posxv += l<<15; posyv += x<<15;
  posz += zvel`. Not `fricxv += l<<5`.
- **SE 29**: `hitag = (hitag+64)&2047`, stored masked.
- **SE 31**: on the arriving tic the sprite loop is skipped, so zero-`zvel` sprites keep
  their old `hittype.floorz`.
- **SE 27 (lead checked):** the camera turn (`getincangle>>3`) and the `yvel` tilt are only
  under `ud.recstat == 2` (`cmp [0xf0d0c],2` at `0x18452`), as in ours; there is no
  `recstat != 2` turn. Differences: no `myconnectindex == screenpeek` test, and `tempang`
  is set in the branches rather than first (display).
- SEs 0, 1, 2, 3, 4, 5, 6/14, 8/9, 10, 12, 13, 15, 16, 17, 19, 20, 21, 22, 25, 30, 32, 33,
  35, 36, 128, 130, 131 and the trailing SE-29 slope loop are 1.0's. SE 0/14/30 set
  `on_sector_effector`, as 1.0 does (`0x15b73`, `0x16816`, `0x187a7`). The
  beta-only native byte is now carried through the real actor paths and codec;
  displayrooms uses it to select the current moving-sector camera.

their CON code (findplayer + execute), and 1.0's movement, timers and the

  uses 1220 too.
- **RECON** (`0x19b9a`): no cansee in the `t[0] >= 4` and `t[0] == 3` tests. Only the

- **HEAVYHBOMB/BOUNCEMINE/MORTER:**
  - The blast radius is **2048** for all three (`0x1af35`; 1.0 2560, G10-A06).

## Doubts and notes for other modules

- movesprite's `zvel >= 1024` gate is odd but is what the code tests.
- WATERDRIP's per-tic krand: confirmed. spawn leaves drips in stat 6 with `zvel = 128`
  (`0x2474e`); makeitfall zeroes `zvel` on landing (`0x2e0cf`); from then on the reset runs
  every tic (G099-061).
- Conveyors: confirmed. The beta's getinput adds no `fricxv`/`fricyv` (`0x3f3b0`; 1.0 adds
  them), so SE 24/34 and 26 move players directly (G099-069, G099-070).
- ifsquished matches the 1.0 EXE, which has no `ud.clipping` test; ours has one. With the
  beta's `clip` cheat that matters (G099-055).
