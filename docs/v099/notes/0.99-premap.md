# premap.c: 0.99 beta compared with 1.0 shareware

Research snapshot: draft ledger statuses below describe the initial audit.
The current implementation status is in the [authoritative plan](../../superpowers/plans/2026-10-21-v099-variant.md#differences-ledger).

## Method

Map: `docs/v10-v11/notes/1.0-premap.md` (the 21 `sw10.bin` functions `0x47580`–`0x4a3c4`).
The 0.99 functions were found as follows:
- `fmatch` pairs the first ten by order, and `cachegoodsprites` exactly (`fmap_beta099.txt`).
- The rest were paired by call graph: prelevel calls resetprestat and setupbackdrop;
  resetpspritevars calls EGS and resetplayerstats; enterlevel calls prelevel,
  resetpspritevars and opendemowrite.

Each pair was compared three ways:
- A normalized instruction diff with masked data addresses (`t4/ndiff.py`, copied to
  `scratch/t5-premap/`).
- The Ghidra decompile of both sides (`scratch/t5-premap/dc10`, `dc99`).
- A `ps`-relative offset listing of every store (`offs.py`).

Every structural claim below was then checked in the capstone disassembly at the address
given. The masked operands were mapped one to one: every `ps` field in these functions is
paired in the field map below, and the globals are named by their other uses (`refs.py`).

The beta's `ps[]` is 8 × `0x33f` bytes at `0xf0f38`. "1.0" offsets are from
`docs/v10-v11/reference.md` ("player_struct (1.0)").

## player_struct fields premap touches

The field map is in `0.99-player.md`, "player_struct". Every store in resetplayerstats,
resetweapons, resetinventory, resetprestat, resetpspritevars, enterlevel and newgame
agrees with it.

Evidence from premap for some of its rows:
- **`return_to_center` `0x33e`.** moveweapons (`0x14616`) and processinput (`0x422e4`,
  `0x422f8`, `0x4231d`) store into it where 1.0 stores into `0x34d`. processinput
  decrements it at `0x42368`–`0x42388`.
- **`auto_run` `0x33d`.** It is read by getinput (`0x3f75b`) and toggled by cheatkeys
  (`0x4ae20`, at `0x4b52a`–`0x4b53d`).
- **`show_help` `0x33a`.** It is toggled at `0x2898a`, which calls vscrn. It is drawn
  full-screen by `0x20c87`, and the main loop tests it (`0x29ed5`).
- **`over_shoulder_on` `0x2c0`.** It is the `view` cheat's toggle (`reference.md`).

**No `wackedbyactor`.** The beta's moveplayers death camera turns toward
`hittype[ps.i].owner` (`0x11cc2`–`0x11d2a`), not toward a `ps` field. There's no slot
between `ammo_amount` and `curr_weapon`. resetplayerstats has no `-1` store for it.

**No fall scream.** No `falling_counter` or `scream_voice` store or read was found in
processinput (`0x40230`): there is no `0x26`/`0x3e` compare and no DUKE_SCREAM (`0xf5`).
The player notes confirm this (G099-091).

## Differences

**P1. resetplayerstats: `return_to_center = 4`** (`0x43544`; 1.0 `9` at `0x479a0`).
- `horiz` starts at 140 (both versions), and processinput eases it toward 100 for
  `return_to_center` tics. With 1.0's step (`horiz += 33 - horiz/3`, the same in the beta,
  `0x4239a`–`0x423a9`), the beta stops easing after 4 tics, at about 108, where 1.0 goes on to about
  101.
- This changes `horiz`, so it changes aim and shot `zvel`. **Demo sync.**
- Port: `source/premap.c:resetplayerstats`, `#if DUKE3D_GAMEVER < GAMEVER_10`
  `p->return_to_center = 4;` `#else` `= 9`. processinput's own value 8 (1.0: 9) belongs to
  the player notes.

**P2. resetplayerstats: no third-person keep, no `fricxv`/`fricyv`, `show_help` per
player.**
- It stores `over_shoulder_on = 0` (`0x43531`). 1.0 and 1.1 keep it on and reset the
  camera (`0x4796c`–`0x4798d`).
- It clears `ps+0x33a` (`0x434df`) where 1.0 clears the global `ud.show_help`
  (`0x47818`).
- It doesn't touch `fricxv`/`fricyv`. 1.0 zeroes them at `0x47aad`. The beta's moveeffectors
  (`0x15630`) and getinput have no such globals.
- It doesn't store `opyoff`, `wackedbyactor` or `falling_counter`, which are absent (above).
- It sets the redraw flag `ps+0x322 = 1` (`0x435a9`) in place of the global `pus = 1`.
- Port: `#if DUKE3D_GAMEVER < GAMEVER_10` `p->over_shoulder_on = 0;` in place of the
  `< GAMEVER_13D` keep block. The rest is display, or fields our 0.99 build can leave
  zero.

**P3. resetinventory: `steroids_amount` is not cleared** (`0x43770`–`0x43819`; 1.0 clears
it at `0x47c98`). The second `inven_icon = 0` is also gone, which is harmless.
- On a new game or a death restart, resetprestat runs resetweapons and resetinventory,
  then resetplayerstats clears steroids only when they are below 400.
- So an unused steroids pickup (400) survives death and a new game. `inven_icon` is still
  0. **Demo sync** (inventory state after a restart).
- Port: `source/premap.c:resetinventory`, skip `p->steroids_amount = 0;` under
  `#if DUKE3D_GAMEVER >= GAMEVER_10` (inside the existing `< GAMEVER_13D` area).

**P4. resetpspritevars: the player sprite is 48 × 44** (`0x44d9e`, `0x44da2`; 1.0 42 × 36
at `0x49366`, `0x4936a`).
- **Demo sync:** sprite size changes hitscan and projectile hits on the player and the
  size-based tests.
- Also in this function:
  - It doesn't store `frag_ps` or `hittype[i].owner = i`. spawn already sets the owner to
    `i` for map sprites (`0x2297f`–`0x2298f`).
  - Palettes are always assigned in sequence from 9 (`0x44e08`), with no
    `ud.last_level == -1` test and no `savedpal[]`.
  - There's no aim-mode save.

  In single player all of these give the same result (pal 9).
- Port: `s->xrepeat = 48; s->yrepeat = 44;` under `< GAMEVER_10`.

**P5. enterlevel: the hurt-floor start strips weapons only.**
- When a player starts on FLOORSLIME (200), HURTRAIL (859) or FLOORPLASMA (1082), the beta
  calls resetweapons only (`0x459e2`). Then: `curr_weapon = 0`, `kickback_pic = 0`,
  `gotweapon[1] = 0`, `ammo_amount[1] = 0` (`0x459ef`–`0x45a07`).
- 1.0 also calls resetinventory (`0x4a1b4`).
- **Demo sync** only if a start spot is on one of those floors.
- Port: `source/premap.c:enterlevel`, skip `resetinventory(i);` under `< GAMEVER_10`.

**P6. enterlevel: quote 40 at every level.** `if (recstat != 2) FTA(40, …)`
(`0x4595b`–`0x4598e`). 1.0 also needs `level_number == 0` (`0x4a109`). This is display:
`fta`/`ftq` are read only by the quote drawer. Port: drop the `ud.level_number == 0` test
under `< GAMEVER_10`.

**P7. enterlevel: other state.**
- **`automapping = 1`** (`0x458c4`; 1.0 `0` at `0x4a079`), which affects map reveal.
- **The map is loaded by name with no 255 suffix.** 1.0 appends `0xff, 0` to keep a loose
  `.MAP` from overriding the GRP (`0x49fe2`). The beta loads
  `levelfile[(vol*9+lev)*13]` (`0x107a70`) as is.
- **A one-shot user map.** A name at `0xa5680` (set by checkcommandline `0x29425`, the
  menus and getpackets) replaces the level file and is cleared after loading
  (`0x457da`–`0x45814`).
- **Fewer `m_` copies.** It copies 4 `m_` fields (recstat, respawn_monsters, `0xf0d10`,
  coop): there's no `respawn_items`.
- **No `ud.last_level = level + 1`** (1.0 `0x4a357`). Nothing in the beta's premap reads
  `last_level`.
- **No prediction copies.** It doesn't copy `hard_landing` or `return_to_center` to the
  prediction globals, and has no `waitabort` MODE_MENU check.

  `everyothertime = 0` and `global_random = 0` are as in 1.0 (`0x45b3d`, `0xb054c`,
  `0x109ff2`).
- Port: under `< GAMEVER_10`, set `automapping = 1` and load
  `level_file_names[...]` directly in the VOLUMEONE branch. The user map and `last_level`
  are optional.

**P8. prelevel: lockout tile.** With `ud.lockout`, FEMPIC1/2/3 all become VIEWSCREENBROKE
(501) (`0x44adc`, `0x44aec`). 1.0 uses BLANKSCREEN for FEMPIC1 and SCREENBREAK6 for the
others (`0x49077`–`0x4909b`). Port: one branch under `< GAMEVER_10`.

**P9. newgame.**
- It sets volume, level, skill, `zoom = 768`, `gm = 0`, `last_weapon = -1` (as in 1.0),
  `ready2send = 0` and `display_mirror = 0`, and builds the multiplayer connect chain.
- Different from 1.0:
  - **`ps[0].auto_run = 0`** (`0x44c11`): a new game turns per-player auto-run off.
  - `ps[0].frag = ps[0].fraggedself = 0` (`0x44bd7`, `0x44bde`).
  - No `show_shareware = 26*34` (1.0 `0x49199`).
  - `last_level` stays untouched, as in 1.0.
- auto_run only feeds getinput (live input, not playback). Port:
  `ps[0].auto_run = 0;` under `< GAMEVER_10`.

**P10. Loading screen and precache.**
- The beta draws the loading screen inside `0x45380`, after resetpspritevars. It shows
  "ENTERING" and the level name: `level_names[vol*9 + lev]`, or `vol*9 + 5` when
  `ud.from_bonus != 0` (`0x4544b`), or the user map name. For demo playback it shows
  "LOADING DEMO...".
- It then runs cacheit's tile loop, from the cachegoodsprites call at `0x45587`.
- There is no getsound or precachenecessarysounds.
- This is display and cache only. The screen itself is a ledger row (G099-044).

**P11. enterlevel: order of the early calls.** Before `MUSIC_StopSong`/`FX_StopAllSounds`,
the beta calls `0x55785` and `0x621fe` (display setup, not identified) where 1.0 calls
dofrontscreens. The music index (`vol*10 + lev`, names at `0xdbc80`), `FX_SetReverb(0)`,
the gm logic and the opendemowrite condition match 1.0.

**krand at level start: unchanged.**
- resetprestat sets `randomseed = 17` before the spawn passes, as in 1.0.
- premap's only own krand is pickrandomspot's multiplayer branch.
- EGS for the APLAYER sprite (`0x22570`, picnum `0x57d`, statnum 10) takes the same
  arguments.
- prelevel's two spawn passes are the same loops in the same order. So the krand order at
  level load is decided entirely inside spawn, which belongs to the actors notes.
