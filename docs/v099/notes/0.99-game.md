# 0.99 vs 1.0: game.c and menues.c

Research snapshot: draft ledger statuses below describe the initial audit.
The current implementation status is in the [authoritative plan](../../superpowers/plans/2026-10-21-v099-variant.md#differences-ledger).

This compares every game.c function in `docs/v10-v11/notes/1.0-game.md`, and the menus range
(loadpheader to the overhead map), in the beta (`beta099.bin`) with its partner in `sw10.bin`.
Each difference is stated against our 1.0 code in `source/`. Addresses are flat image
addresses (base `0x10000`). The 0.99 guard is `DUKE3D_GAMEVER < GAMEVER_10`.

## Method

1. **Pairing.** fmatch pairs only 7 of these functions (`fmap_beta099.txt`). The rest were
   paired by order, size, callees and strings. The beta's game.c runs from `0x1c700` to
   `0x2d9b4`, after actors.c. The pairs are in the scratch folder `t5-game/pairs.txt`.
2. **Normalized diff.** `t5-game/nd.py` disassembles each pair with capstone. It drops
   registers, `[esp+N]` offsets and local jump targets, masks data addresses, and maps calls
   through fmatch, the pair list and the Address map in `reference.md`. Every pair with more
   than scheduling noise was read in the disassembly or in Ghidra decompiles
   (`t5-game/dc10`, `t5-game/dc99`).
3. **spawn.** `t5-game/tw3.py` walks both picnum compare trees for every value from 0 to 8191
   (1.0 head `0x175f7`, beta `0x22cdf`). It is the 1.0 work's `tw2.py`, except that it steps
   over `lea/add/sub ebp` instructions the compiler mixes into the tree. Landings were
   grouped, and bare returns folded together. Each matching case pair was compared as a
   control-flow trace (`t5-game/cases.py`) with sprite, hittype, sector, wall and ps operands
   turned into field offsets. The bases are 1.0 `0x1a6d1c`, `0xda370`, `0x21f01c`, `0x1d3d1c`
   and `0x112ab0`, and beta `0x18ce5c`, `0xb8480`, `0x20515c`, `0x1b9e5c` and `0xf0f38`. Then
   the stores and calls were compared as multisets (`cs2.py`), which ignores reordering.
   Every flagged case was read by hand.
4. **Map reach.** `t5-game/maps.py` and `maps2.py` count the affected picnums, and their
   cstat, lotag and extra, in the six beta maps.

## 1. domovethings, and the callers of processinput

domovethings (`0x2bab0`) runs, in order:
1. `camerasprite = -1`, `lockclock += 4`, and a user-quote countdown (`0x109ff0`).
2. The fifo-to-`sync[]` copy, then `movefifoplc++`.
3. `earthquaketime--`.
4. `syncval[...] = randomseed & 255` every tic. It has no `numplayers >= 2` or `& 7` test, and no ps sum. This is network only.
5. `everyothertime++`, then record when `recstat == 1`.
6. When not paused: `global_random = krand()` and movedummyplayers.
7. For each player: cheatkeys (`0x4ae20`), then processinput (`0x40230`) and checksectors (`0x4b880`) when not paused.
8. The movers, in 1.0's order (including moveexplosions, moveeffectors, moveactors).
9. Every other tic: animatewalls and movecyclers.
10. **Last of all:** fakedomovethingscorrect (`0x2b850`).

Against our 1.0 path:
- **None of 1.0's quit-bit (`1<<26`) handling.**
- **No `rtsplaying` or `show_shareware` countdown.**
- **No `pan3dsound` here.** The main loop and playback call it once per drawn frame
  (`0x4cef0`, after nextpage).
- **fakedomovethingscorrect comes after the every-other-tic block, not before it.** It does
  nothing in single player.
- The krand and mover order is 1.0's.

processinput's other caller is fakedomovethings (`0x2aad0`), which only runs in multiplayer.

## 2. Main loop (`0x29b70`)

- **Startup.** It prints `Duke Nukem 3D Pre-Release "Beta" version .99` and "Press any key
  to continue", then waits for a key. Next come checkcommandline, Startup and loadtmb, then
  the CON compile. If the compile fails, "Compiling CONs in GRP" recompiles from the GRP.
- **Title loop.** If not warping: Logo, then playback until it returns 0. If warping:
  `newgame(m_volume, m_level, …)` and `enterlevel(MODE_GAME)`.
- **The in-game tic loop for single player is 1.0's:** getpackets, then domovethings until
  `movefifoplc == movefifoend[myconnectindex]`.
- **MODE_EOL / MODE_RESTART:**
  - On EOL it calls `vscrn` (`0x431d0`) and dobonus.
  - If `level_number == 5 && from_bonus == 0`, it calls doorders, sets `gm = 0` and returns
    to the title loop. 1.0 instead sets `gm = MODE_MENU`, calls `cmenu(0)` and, in
    multiplayer, resets volume and level.
  - Otherwise it calls `enterlevel(gm)`. There is no `numplayers > 1` → `MODE_GAME`.
- **Each frame:**
  1. cheats and nonsharedkeys.
  2. displayrooms, with the same smoothratio rule as 1.0.
  3. `if (gm & MODE_DEMO) goto title`.
  4. displayrest and checksync.
  5. `minitext(266,3,"BETA VERSION",0,2+8+16+128)` every frame, with no menu or
     show_shareware test. 1.0 draws the BETAVERSION tile at (270,9) while
     `show_shareware > 0` and not in a menu.
  6. nextpage, then pan3dsound.

Beta `gameexit` (`0x20930`) calls Shutdown and then displays the4000-byte
DOS text asset `DUKE3D.BIN`; it has no graphical exit ads or key waits.
The native beta excludes1.0's `showtwoscreens` call (G099-129), whose
tiles3290/3291 are empty in beta data. Native text-mode output retains the
port's existing platform policy.

## 3. playback (`0x2a560`): the demo loop

These differences go in our `playback()`, and the sync ones also in `demoverify()`:
- **The tic loop is `while (totalclock > lockclock)`** (`0x2a737`). 1.0's is
  `totalclock >= lockclock+4`. This only changes when tics run.
- **MODE_RESTART restarts the level inside the demo.** After each batch of tics,
  `if (gm & MODE_RESTART) enterlevel(MODE_DEMO)` (`0x2a83a`–`0x2a85b`), and playback goes
  on. 1.0 has no such test, because its processinput closes the demo when the player dies.
  - **This is sync relevant.** A death in a beta demo resets the level and keeps reading
    records.
  - The check sits after the whole batch, so in DOS any tics left in the batch run with the
    flag set before the restart. A headless port should restart straight after the tic that
    sets it, which is DOS's case at one tic per frame. See Doubts.
- **MODE_EOL ends the demo.** After drawing, `if (gm & MODE_EOL) return 1` (`0x2a8ab`), with
  no `kclose`. 1.0 loops on to the next demo only when both MODE_MENU and MODE_EOL are set.
  Our demoverify should stop at MODE_EOL.
- **The return is the same as 1.0's.** At the end of the records: `kclose`, then return 1.
  It does not loop back for MODE_MENU. On `gm == MODE_END || gm == MODE_GAME`:
  `recstat = 0`, `kclose`, return 0.
- **Drawing and UI:**
  - Text: `minitext(266,3,"BETA VERSION",0,154)` with a demo, `minitext(291,2,"NO DEMO",0,154)`
    without one. There is no BETAVERSION tile, no MODE_TYPE branch and no operatefta call.
  - ESC (or bit 7 of `0x10c3de`) clears the key, stops sounds, sets MODE_MENU and calls
    `cmenu(0)`. It does not call intomenusounds.
  - The start does not reset `pub`/`pus` and does not call `flushperms`.
- `which_demo` wraps 4 → 1, as in our `< GAMEVER_13D` code.

## 4. spawn (`0x228f0`)

The pre-switch code is the same as 1.0's. The hittype init writes the same fields, with
`timetosleep = 0` among them. Map reach is from the six beta maps.

**Compare tree.** It differs from 1.0 for these picnums only:

| Picnum | 1.0 | 0.99 | Beta maps |
|---|---|---|---|
| FORCESPHERE | case at **2590** | case at **1220** (beta `DEFS.CON`: `FORCESPHERE 1220`); 2590 is a bare return | 0 |
| FEM4 (1325), PODFEM1 (1294) | FEM group | bare return (no lotag/extra/cstat, stays stat 0) | FEM4: 1 on E1L5 |
| TRASH (1272) | `ang = krand&2047`, then the WATERDRIPSPLASH body | bare return | 0 |
| DUKECAR (2491) | DUKELYINGDEAD group | bare return | 0 |
| OCEANSPRITE4 (974) | `changespritestat(i,0)` only | joins the group above it: `clipdist = 32; cstat |= 257`, stat 0 | E1L3: 8, E1L4: 11 |

The beta `DEFS.CON` has no TRASH, DUKECAR, FEM4 or PODFEM1 (`FEM4` is still placed on E1L5
as tile 1325). Every beta use of FORCESPHERE is 1220: spawn `0x231aa`, animatesprites
`0x266ce`, moveactors `0x1952c`/`0x19b5a`, moveexplosions `0x1b95a` and `0x498c5`.

**Case bodies.** These differ:
- **WATERDRIP** (`0x246de`). Our code is the `< GAMEVER_13D` branch, followed by the TRASH
  fall-through:
  ```c
  if (j >= 0 && sprite[j].statnum != 6) {
      if (sprite[j].statnum == 10 || sprite[j].statnum == 1) { sp->shade = 32; sp->pal = 2; }
      sp->z -= (13<<8);
  } else T1 = sp->z;            // no z += 4<<8
  sp->zvel = 128;
  sp->xrepeat = sp->yrepeat = 24; changespritestat(i,6);
  ```
  - There is no getangle, no `xvel` krand and **no TRASH `ang = krand&2047`**. A map
    WATERDRIP takes **0 krands** at prelevel, where 1.0 takes 1. Spawned drips take 0, where
    1.0 takes 2.
  - **This shifts krand on load:** E1L2 2, E1L3 1, E1L4 2, E1L5 1, E1L6 3.
- **CAMERA1..+4, CAMERAPOLE, GENERICPOLE** (`0x24ecc`): `sp->extra = 0; sp->cstat = 257;`
  unconditionally, before the `multimode < 2 && pal` test. 1.0 leaves cstat as mapped.
  - The beta maps have 95 of these (54 CAMERA1, 41 GENERICPOLE), almost all with cstat 0.
  - In the beta they become **blocking and hitscan-able**. This is sync relevant.
- **Badguys** (`0x2499c`–`0x249f1`): `sp->cstat = 257` (assignment) where 1.0 has
  `cstat |= 257`. 1.0's explicit `timetosleep = 0` for `j >= 0` is redundant with the
  pre-switch, and the beta has neither. Map badguys have cstat 0, 1 or `0xc`, so this
  drops the flip bits (`0xc`) on 4 sprites.
- **TRIPBOMB** (`0x23cae`): if `lotag > player_skill`, size 0 and **no
  `changespritestat(i,5)`**. The sprite stays in stat 0. E1L4 has a lotag-2 tripbomb, so this
  applies at skill < 2.
- **FEM1–3** (`0x23faa`): `lotag = 1; extra = max_player_health>>3; cstat = 257;
  clipdist = 8;` stat 2. This is 1.0's body without the PODFEM1 `extra <<= 1`.
- **DUKELYINGDEAD** (`0x23fde`): the APLAYER copy, then `cstat = 0; extra = 1;` stat 1. There
  is **no `xvel = 292`, `zvel = 360`**.
- **RESPAWN** (`0x24301`): `sprite[i].shade = 53` instead of `extra = 66-13`. The rest
  (size 0, cstat 0, stat 11) is 1.0's. Map RESPAWNs have `extra = -1` (163 sprites), and the
  beta keeps that.
- **PLAYERONWATER** (`0x24446`): `sp->cstat |= 32767` (`or word [esi+0xc],0x7fff`) instead of
  `|= 32768`. The dummy-player sprite gets blocking, hitscan, flip and alignment bits.
- **WATERSPLASH2** (`0x23712`):
  - Size `16+(krand&15)` in both branches, as in our `< GAMEVER_14` code.
  - With `j >= 0`: lotag 2 gives `sp->z = sector[sprite[j].sectnum].ceilingz + (16<<8); cstat |= 8`.
  - Otherwise `sp->z = sector[sect].floorz`, where `sect` is the sector at spawn entry.
  - There is no slope lookup (1.0 calls `getceilzofslope`/`getflorzofslope`).
- **WATERBUBBLE** (`0x24512`): `xrepeat = yrepeat = (krand&3)+2`. 1.0 has `(krand&7)+1`. The
  krand count is the same.
- **MONEY** (`0x2411b`): `sp->cstat |= krand&12`, where 1.0 has `=`. The krand count is the
  same.

These are the same as 1.0: SE27 with `recstat == 1` sets the size only (`0x25138`), BLOODPOOL
(probe order and sector seed), SHELL/SHOTGUNSHELL, CRANE, LIZTROOP pal, the bosses,
FOOTPRINTS and the rest.

## 5. Glass

lotsofglass, wall branch (`0x2d1d7`–`0x2d2cb`): after `updatesector(x1,y1,&sect)` there is
**no `if (sect >= 0)`**. It always draws `z` from `sector[sect]` and runs the rest of the
body. When a point is in no sector:
- **This changes the krand count.** It takes 4 krands where 1.0 takes none.
- It reads `sector[-1]`: the last 40 bytes of the engine `palette[]` (`0x204e5c`, which
  ends where `sector[]` starts, `0x20515c`). With the beta's PALETTE.DAT that gives
  `ceilingz = 0x3f290029` and `floorz = 0x163f00`, so the first `z` (one krand) always
  fails the ±8192 test and the fallback `SZ-(32<<8)+(krand&0x3fff)` is used, followed by
  the two velocity krands.
- EGS uses the sprite's own sector (`[ecx+0x18ce74]`, `0x2d2b2`), not `sect`, so nothing
  is written out of bounds. G099-021 copies this outcome without the read (rulings).

`sect` is not seeded, as in 1.0. lotsofcolourglass has no test in 1.0 either, so it matches.

## 6. Cheats (`0x27820`), command line, keys

- **cheats.**
  - **Entry:** the same D/N sequence, gated on `numplayers < 2 && recstat == 0`. So cheats
    never run in demos.
  - **Gate:** current menu not in 360–369 and no MODE_TYPE.
  - **Typed characters:** `a`–`z` and `0`–`8`. Any other key, a buffer longer than 7, or no
    match: `cheat_phase = 0` and quote 46.
  - **Quotes:** each FTA is shown only when `ud.fta_on` (`0xf0cec`) is set.
  - **Effects** (15 codes, the reference "Cheats" table):
    - `godly`: `god = 1`, quote 17, and it sets both redraw flags on `ps[screenpeek]`. There
      is no sprite or hittype reset.
    - `ungodly`: `god = 0`, quote 18.
    - `warp##`:
      - Volume = digit 1 − 1 and level = digit 2 − 1, **with no range check**. It also sets
        `player_skill` and `m_player_skill` to digit 2 − 1 (shared with `skill#`).
      - Then MODE_RESTART; in multiplayer it sends packet 5 instead.
      - It clears `0xa5680` (the user-map name).
    - `ammo`: `addammo(w, p, max_ammo_amount[w])` for weapons 1–9, quote 20.
    - `view`: toggles `over_shoulder_on`, quote 22. There is no `cameradist`/`cameraclock`
      reset.
    - `weapons`: `gotweapon[1..9] = 1`, quote 21.
    - `unlock`: walks sectors from last to first:
      - It skips lotag −1 and 32767, and takes sectors with `(lotag & 0x7fff) > 2`.
      - For those, it clears bit `0x4000`, then `operatesectors(i, ps.i)`.
      - Then `operateforcefields(-1)` (one-argument form, `0x47d10`), quote 4.
    - `cashman`: toggle, clears N. No quote.
    - `items`: 1.0's `items` values, plus `0x298 = 1600`, quote 5.
    - `rate`: toggles tickrate.
    - `skill#`: skill = digit − 1, then MODE_RESTART.
    - `clip`: toggles clipping, quote `44 + clipping`.
    - `hyper`: steroids 399, heat 1200, quote 37.
    - `monsters`: cycles `actor_tog` 1–3.
    - `ending`: `level_number = 5; gm |= MODE_EOL`, without resetting `cheat_phase`.
- **checkcommandline** (`0x29390`):
  - **Defaults:** `fta_on = 1`; god, warp_on, `m_respawn_monsters` and cashman = 0.
  - **Skill and level switches:**
    - `/l#` sets warp_on, `m_level` and `level_number` to `#−1`, **and sets both skills to 2**.
    - `/v#` sets warp_on, `m_volume` and `volume_number`.
    - `/s#` sets both skills to `#−1`, without warp_on.
  - **Other switches:**
    - `/t` sets `m_respawn_monsters = 1` only.
    - `/m`, `/r`, `/c`, `/q#` (capped at 8) and `/n0`/`/n1` work as in 1.0.
    - `/d` sets `0xf098b`.
    - `/i` and `/o` set the input and output paths.
    - `/~` sets the music test (`0xa56d0`).
  - An argument containing `map` is taken as a user map: name to `0xa5680`, `m_volume = 3`,
    `m_level = 8`, warp_on.
  - The help text says `/s#   Skill # (0-3)`.
- **nonsharedkeys** (`0x284c0`):
  - **Screenshot:** to `duke0000.pcx`, with quote 103.
  - **F1 help:** toggles a per-player byte (`ps+0x33a`), and displayrest draws one F1HELP
    page (2445) until ESC.
  - **Save and load:** F2 opens the save menu (350, after a 160×100 thumbnail into
    `d3d.tmp`). F3 opens load (300), F4 sound (700).
  - **Messages and quick keys:** F5 toggles `0xf0d24` (quotes 26/27). F8 toggles fta_on
    (quotes 23/24). F6/F9 are the quick save and load.
  - The rest is the usual view-size, map and gamma keys. This is UI and was not itemized.

## 7. Title, logo, shareware and beta screens, menus

- **Logo** (`0x29720`). There is no getpackets and no "WAITING FOR PLAYERS". In order:
  1. KB flush, then `playmusic(env_music_fn[0], …)`, then fade out.
  2. `palette = drealms`, DREALMS for 960 tics or a key.
  3. Fade, `palette = titlepal`, then **`sound(PIPEBOMB_EXPLODE)` once, here**, then
     BETASCREEN with a fade in.
  4. A loop to 980 tics or a key:

## 8. HUD, view and display code that touches game state

- **`ps+0x322`** is a per-player **status-bar redraw flag**. 1.0's `pus` is global.
  - Set to 1 by: FTA (when the quote changes), the cheats, nonsharedkeys, saveplayer
    (`0x35a98`), the CON `addphealth`/`addinventory` handlers, addammo/addweapon/
    checkavailweapon, processinput, quickkill (`0x3a893`), `0x47df0` and `0x4ae20`.
  - loadplayer clears it (`0x35541`).
  - **Only coolgaugetext reads it** (`0x1f4ce`): `if (p->0x322 > 0) { p->0x322 = 0; redraw
    the bar }`.
- **`ps+0x324`** is a per-player **border redraw counter**, 1.0's `pub`. FTA and the same UI
  sites set it. displayrooms (`0x219af`) runs `if (p->0x324 > 0) { if (ud.screen_size > 7)
  drawbackground(); p->0x324--; }`.
- **`ps+0x260`** is the **palfrom expiry clock**:
  - Set to `totalclock + N`: CON `palfrom` (+32), processinput (3 sites) and quickkill.
  - **displayrest** (`0x20b9b`):
    - `if ((totalclock>>1) < (p->0x260>>1) && p->loogcnt == 0)` it calls
      `palto(pals[0], pals[1], pals[2], ((p->0x260 - totalclock)>>1) + 16)` and sets
      `restorepalette`.
    - Otherwise it does 1.0's restore, loogcnt and heat branches.
  - This replaces 1.0's `pals_time`. It is display only.
- **`ps+0x2d8`** is **`timebeforeexit`**. processinput (`0x406c8`) runs
  `if (p->0x2d8 > 1 && p->last_extra(0x27a) > 0) { p->0x2d8--; if (== 78) … }`. 78 is 26×3,
  where our player.c has 26×5. The CON `palive` test reads it (C099-017). This is the player
  module's.
- **displayrest:** when `p->show_help (0x33a) == 1` it draws F1HELP (2445) full screen and
  closes it on ESC. The pause text is "GAME PAUSED" via menutext. It does not mark
  `show2dsector`; the engine does that.
- **animatesprites** (`0x27616`): for SHELL/SHOTGUNSHELL it does
  `T1 = (T1+1)&3` **every drawn frame**, then the tsprite cstat flips. That is a game-state
  write at frame rate. It touches only `hittype.temp_data[0]` of shells, with no krand and no
  movement. The headless demoverify draws no frames. Not in STATE.BIN.
- **view** (`0x21290`): the third-person camera is a clipmove from the player back along the
  view.
  - It clears `0x101` on the player sprite and sets it back (`|= 0x101`).
  - On each sprite hit, it clears `0x101` on that sprite, retries, then **sets `|= 0x101` on
    it**.
  - Reachable only through the `view` cheat.
- **check_fta_sounds:** BOSS1 plays `spritesound(BOS1_RECOG, i)` where 1.0 uses
  `sound(BOS1_RECOG)`.

## Doubts

- **MODE_RESTART in playback.** In DOS the restart happens after the remaining tics of the
  current batch. Those tics run with `gm & MODE_RESTART` set, and their number depends on
  frame timing. One per frame is the usual case. A death inside a reference demo should
  show whether this matters.
- **lotsofglass with `sect = -1`.** Settled: EGS uses the sprite's own sector, and the
  out-of-bounds read is the end of `palette[]`, whose value forces the fallback `z`
  (section 5). Copied without the read (G099-021, rulings). Whether a shipped map reaches
  it was not measured.
- **RESPAWN.** Settled: the beta keeps the whole timer in `shade`. movefx spawns at
  `shade == 66` and counts up past 53 (`0x11ee2`–`0x11f11`); operaterespawns sets 54
  (G099-015).
- **`warp##` with no range check.** Fixed, not copied: digits that name no defined level
  are ignored (G099-023, rulings).
- **Not itemized:** nonsharedkeys and HUD drawers beyond the redraw flags. Menu and
  bonus differences are itemized in section 7; backend details remain port infrastructure.
