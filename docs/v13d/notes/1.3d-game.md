# game.c: 1.3D (0x101d0 to 0x248df) compared with source/game.c

**How the work was split.** I (the parent agent) did spawn. Three parallel helper agents did the rest:
- Fork A: render, UI and helper functions.
- Fork B: cheats, main and the bonus screens.
- Fork C: networking, demos and the movethings functions.

Where the forks conflicted, I checked the asm myself.

**Scratch files and tools.** Everything is under `<scratch>/`:
- `tools/dis.py <start> <end>` disassembles full13.bin with capstone.
- `tools/sw.py` recovers spawn's switch exactly by walking the Watcom compare tree for every picnum from 0 to 8191. Its output is `g13/game/spawn_cases.txt`, and the spawn asm is `g13/game/spawn.asm`.
- The decompiles are in `g13/game/<addr>.c`.

"Ours" line numbers refer to `source/game.c`.

## 2. Differences

### spawn (0x17b30)

**The biggest difference: 1.3D's spawn has no default case.** Any picnum not in the switch returns `i` unchanged. Both default targets, 0x17f30 and 0x1ba22, are `mov eax,edi; add esp,0x28; pop…; ret`. 1.3D has no `actortype[]` at all; it is also missing from the save file.

## 4. Not mapped or not checked

- **Drawing only, not compared line by line:** drawbackground, weaponnum, weaponnum999, weapon_amounts, digitalnumber, displayinventory, displayfragbar, invennum, myos, myospal.
- **doorders (about 0x22560):** found but not called, and not compared.
- **Unknown addresses:** 0x14d859 (set by /d), 0x14f724 (main loop flag), and 0x77617 (sendlogon or uninitmultiplayers).
- **getpackets case 7:** the RTS gating is not verified in the asm.
- **0x1cdbae:** the global that WATERDRIP reads as sprite[-1].statnum is not identified.
- **Coupled work in actors.c:**
  - FRAMEEFFECT1 = 3999
  - SE18, SE23 and SE28 lose their init
  - SE25 uses T5 rather than T4
  - SE31 sets T3 = hitag
  - SE6/14 have no lastvx
  - RANDOMSCRAP argument evaluation order
