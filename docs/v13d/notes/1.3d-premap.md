## premap.c vs 1.3D (full EXE): report

The 1.3D premap module runs from **0x4ad50 to 0x4debd**. It starts earlier than the 0x4bcf0 you estimated. processinput ends at 0x4ad49, and 0x4ad50 is xyzmirror. The last function is enterlevel (0x4d950–0x4debd). sector.c starts at 0x4dec0, which calls the sound functions and is called by doanimations 0x4e580. 1.3D's player.c has no computergetinput.

Decompiles and the enterlevel disassembly are in `<scratch>/g13/premap/`. Helper scripts I wrote, both run with `python3 -I`:
- `<scratch>/g13/dis.py` disassembles a range with capstone.
- `<scratch>/g13/xref.py` scans the whole code for an operand string.

**1.3D ps layout (needed to read any 1.3D code; stride 0x552):**
- Fields up to `crack_time` are the same as ours.
- **There is no int32 `aim_mode` at 0x280.** It is a char at **0x534**. Evidence: resetpspritevars saves and restores it per player, and sector.c 0x53350 toggles it.
- 0x280–0x28a: ang, oang, angvel, cursectnum, look_ang, last_extra. **There is no `subweapon`.**
- `ammo_amount[11]` at 0x28c, so **MAX_WEAPONS = 11**.
- wackedbyactor 0x2a2, frag 0x2a4, fraggedself 0x2a6, curr_weapon 0x2a8, last_weapon 0x2aa, tipincs 0x2ac, horizoff 0x2ae. **There is no `wantweaponfire`.** holoduke_amount is 0x2b0, newowner 0x2b2; from there through actorsqu (0x2ea) the order is ours.
- `weaprecs[256]` at 0x2f0, weapreccnt 0x4f0, rotscrnang 0x4f4 … boot_amount 0x510, scream_voice 0x512.
- gm 0x516, on_warping_sector 0x517, footprintcount 0x518, hbomb_on 0x519, jumping_toggle 0x51a, rapid_fire_hold 0x51b, on_ground 0x51c.
- 13 bytes at 0x51d–0x529 are unidentified.
- inven_icon 0x52a … falling_counter 0x533, aim_mode 0x534, gotweapon[11] 0x535, refresh_inventory 0x540, palette 0x541, toggle_key_flag 0x545 … palookup 0x548 … return_to_center 0x551.

### 3. Checked and equivalent
- xyzmirror and vscrn (render).
- resetweapons: loops 1..10 with MAX_WEAPONS=11; same assignments.
- resetinventory.
- resetprestat apart from the spriteq bound. The 14 global resets (randomseed=17, two -1s, ten zeros) match in count and kind, and the weapon/inventory condition and HANDREMOTE→HANDBOMB swap are the same.
- prelevel apart from the rows above.
- resetpspritevars apart from the palette: EGS, aim/tsbar save/restore, memcpy, po[], sprite init, last_extra, positions, updatesector, deletesprite.
- newgame apart from the rows above: dobonus condition, ud fields, zoom/gm, m_coop weapons, connect setup.
- resetmys (inlined).
- The enterlevel floor-picnum loop (FLOORSLIME 200 / HURTRAIL 859 / FLOORPLASMA 1082), gm logic, opendemowrite condition, last_level, bakipos restore, everyothertime/global_random, playerquitflag.
- cachespritenum and cachegoodsprites write no globals (tile loads only).
- krand order: the only krand in the module is pickrandomspot in both versions. During level load, randomseed=17 is set in resetprestat before the spawn passes, in the same order.

### 4. Not fully checked
- cachespritenum and cachegoodsprites picnum lists: compared only for side effects. They are cache-only, with no state or krand.
- The 13 unidentified ps bytes at 0x51d–0x529, and the exact names of the fifo/net globals in the clearfifo-like blocks: these need the game.c netcode mapping.
- dofrontscreens and enterlevel drawing calls (0x5fb92 used as nextpage vs drawbackground): render-only, not pinned down.

**Atomic-only special cases in our code that 1.3D lacks:**
- the Episode 4 intro ANMs in newgame;
- the SCREENBREAK14–19 animwalls in prelevel;
- the CLOUDYOCEAN parallax case in setupbackdrop (1.3D has no handling for it, though the tile itself may not be Atomic-only);
- the ffire copy in enterlevel;
- GROW_WEAPON (MAX_WEAPONS 12 vs 11).
