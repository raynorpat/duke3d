I mapped all of 1.3D's player.c to our file and compared everything except the display/HUD functions. I found about 30 state-affecting differences. The decompiler mangled the control flow badly in places, so I checked every structural claim below against the disassembly; several apparent differences turned out to be decompiler artifacts and are listed as equivalent. All addresses are 1.3D full-EXE addresses and all line numbers are in source/player.c.

## 1. Function map

player.c runs from 0x41d40 to 0x4ad49. Everything from 0x40850 to 0x41c6a still belongs to menues.c: 0x40970 calls only the drawing helpers, and 0x41a70 is playanm (it calls kopen4load/kread). premap.c starts at 0x4ad50, which calls the mirror and drawing routines, so it is xyzmirror.

## 3. Checked and equivalent

- setpal, incur_damage, quickkill, forceplayerangle, tracers (same krand count and order), hits, hitasprite.
- doincrements: every branch and constant matches.
- shoot cases: FIRELASER/SPIT/COOLEXPLOSION1, BOUNCEMINE/MORTER, SHRINKER, and the shooter-position header (crack_time 777, ROTATEGUN/COMMANDER offsets). Within SHOTSPARK, the player aim/krand order and the bullethole/dipswitch logic match. In RPG, the BOSS2/BOSS3/DEVISTATOR offsets and krand order match.
- processinput: sync bits handling, getzrange, the slope horizoff code, the underwater/jetpack/walk vertical physics, jumping, turning (avel*2, and -(>>3) underwater), friction, movement, pyoff, the horizon keys and clamps, knee_incs/actorsqu, weapon_pos, rapid_fire_hold.
- processinput weapon start and animation for HANDBOMB, HANDREMOTE, PISTOL, SHOTGUN, SHRINKER, DEVISTATOR, FREEZE, RPG.

The decompile suggested breakage in FREEZE, SHOTGUN, HANDREMOTE and CHAINGUN, but the disassembly shows those were decompiler artifacts.

## 4. Not mapped or not fully checked

- Display functions (displayloogie, animatefist/knee/knuckles/tip/access, displaymasks, displayweapon): mapped but not diffed, because they are render-only. Our versions write no game state. 1.3D displayweapon calls C rand() (0x9e875), which is not krand.
- getinput: only checked at the level of bit layout and velocity constants.
- Three cross-module items for whoever owns those files:
  - checksectors (sector.c) uses hitawall's 0 return.
  - The CON tossweapon / checkweapons interaction (gamedef.c).
  - The 1.3D CON value of gc.

Working files (decompiles, pi.asm, shoot.asm, and the dis.py/nm.py helpers) are in <scratch>/g13/player/. 47760.c there was regenerated with real arguments, because the shared dc_full copy had none.
