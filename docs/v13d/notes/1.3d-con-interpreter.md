## 1.3D vs our CON interpreter: behavioral differences

I found nine real differences. Seven are in `parse()`: `sizeto`, `addweapon`, `addphealth`, `debris`, `resetplayer`, `ifp`, `ifspawnedby`, `ifgotweaponce` and `respawnhitag`. There are none in `execute()`, `move()`, `alterang()`, `furthest*()`, `dodge()` or `parseifelse()`. I checked the two riskiest decompile readings, `sizeto` and the `debris` call site, against Ghidra disassembly (Disasm.java on 0x36e50; listing at `<scratch>/parse.asm`). Neither is a decompiler artifact.

To read the `ps[]` offsets, I rebuilt the 1.3D `player_struct` layout from offsets confirmed in the decompile:
- It has no `aim_mode`, no `subweapon` and no `wantweaponfire`.
- `ammo_amount` has 11 entries (no grow weapon) and `weaprecs` has 256.
- Key offsets: `ang` +0x280, `ammo_amount` +0x28c, `wackedbyactor` +0x2a2, `curr_weapon` +0x2a8, `newowner` +0x2b2, `kickback_pic` +0x2c8, `quick_kick` +0x2e6, `actorsqu` +0x2ea, `weaprecs` +0x2f0, `weapreccnt` +0x4f0, `rotscrnang` +0x4f4 (inferred), `dead_flag` +0x4f6, `gotweapon` +0x535, `pals` +0x54c.

`ud` fields: `ud.coop` = 0x14de32, `multimode` = 0x14dde4, `respawn_monsters/items/inventory` = 0x14de42/46/4a, `player_skill` = 0x14de7e, `god` = 0x14d854, `eog` = 0x14d857.

## Checked and equivalent

**`parse()` cases**
- **`ifrnd`**: one krand, `(r>>8) >= 255-arg`.
- **`ifcansee`**: two krand masks, 0x1fff (holoduke) and 0x2f00. Same lastvx/lastvy logic, `furthestcanseepoint` fallback and SLEEPTIME.
- **`ifhitweapon`, `ifsquished`, `ifdead`**: same.
- **`action`, `ai`**: random_angle uses one krand, `&2047`.
- **`ifpdistl` / `ifpdistg`**: MAXSLEEPDIST 16384, SLEEPTIME 0x600.
- **Control flow**: `else`, `strength`, `break`/`enda`/`ends`, `state`, `{`, `}` and `killit` (returns 0) match.
- **`fall`**: equivalent. Gravity is 176/29 (we set `gc=176` for 1.3D at gamedef.c:1357). Same cgg handling, FOURSLEIGHT, zvel cap 6144, jibs/THUD/pushmove thresholds and constants, and the OCTABRAIN/COMMANDER/DRONE water exemption.
- **Simple actions**: `shoot`, `palfrom`, `sound`, `spawn` (with sector check), `move`, `cstat`, `count`/`resetcount`, `resetactioncount`, `cactor`, `spritepal`, `getlastpal`, `tip`, `quote`, `addkills`, `money`, `lotsofglass`, `guts`, `hitradius`.
- **Simple conditions**: `ifwasweapon`, `ifaction`, `ifactioncount`, `ifmove`, `ifai`, `ifactor`, `ifstrength`, `ifcount`, `ifactornotstayput`, `ifspritepal`, `ifphealthl`, `ifnotmoving`.
- **Sound**: `soundonce`, `stopsound`, `globalsound` and `mikesnd` match.
- **`addammo`**: same, including the knee check.
- **`addinventory`, `ifpinventory`**: all sub-cases and pal 0/21/23 bits.
- **`pstomp`**: same knee_incs/xrepeat≥40/cansee offsets.
- **`pkick`**: same.
- **`ifcanshoottarget`**: same sclip/angdif (768/16, 3084/48), three `hitasprite` probes, same-picnum checks.
- **`ifcanseetarget`**: krand&41.
- **`ifonwater`, `ifinwater`, `ifgapzl`, `iffloordistl`, `ifceilingdistl`, `ifawayfromwall`**: ±108 offsets.
- **`ifhitspace`**: bit 29. **`ifmultiplayer`**: same.
- **`ifbulletnear`**: calls `dodge`. **`ifrespawn`**: badguy, then inventory, then items.
- **`operate`**: same neartag args and sector-lotag gates. **`endofgame`**: same.
- **Unknown opcodes**: both set `killit_flag=1` (1.3D treats everything from 98 up as unknown).

**Other functions**
- **`execute()`**: same insptr start (+16 bytes) and bad-sector kill. Same animation counter: lotag += 4 (TICSPERFRAME = 120/26 = 4 in ours too), then the t2/t3 updates. After the parse loop: killit_flag==1 clears actorsqu and deletes the sprite; otherwise `move()` runs. The statnum 1 checks (xrepeat>60, respawn_monsters/items) and the statnum 6 picnum list (11 entries, identical) also match.
- **`move()`**: all flag branches match:
  - faceplayer, spin, faceplayerslow, jumptoplayer (t0<16) and faceplayersmart (/768) behave the same.
  - The `t1==0||a==0` setsprite path matches.
  - geth and getv apply in the same order, then dodgebullet, then alterang for non-players, then the ±6 xvel deadzone.
  - DRONE/COMMANDER/ORGANTIC z clamps use the same constants: 0x800, 0x5000, 0x3200, 0x1e00 and 0x4200.
  - The g_x<960 push uses the same `dukefriction-0x2000`.
  - The frame skip `bposz==z && (multimode>1 || skill>1)` is De Morgan-equivalent to ours.
  - The `movesprite` call (CLIPMASK0), the shade update and the MIRROR delete match.
- **`alterang()`**: same /5 smoothing and zvel<648. seekplayer uses holoduke cansee. ticselapsed<2 does one krand, `128-(r&256)`, then hits<844. The 19..25 window also matches. When ticselapsed is 0, furthestdir and fleeenemy both use `furthestangle(i,2)`.
- **`furthestangle()`**: same early return `ang+1024` and z-(8<<8) hitscan with zvect 0.
- **`furthestcanseepoint()`**: same `t0&63` gate. angincs is 1024, or `2048/((r&1)+1)`. Per iteration, one krand for zvect `16384-(r&32767)` comes before the hitscan, and one krand for the step `-(r&511)` comes after the body, in the same order as ours. Ghidra shows the hitscan's xvect argument coming from krand's high half. That is an artifact of the register-preserving Watcom call: the value is `j`.
- **`dodge()`**: same tests and 0x400000 threshold. It does one krand: `ang -= 512+(r&1024)`.
- **`parseifelse()`**: identical.
