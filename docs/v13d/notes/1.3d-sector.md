## sector.c vs 1.3D: report

**The module's range is different from the estimate.** sector runs from **0x4dec0 to 0x54bf0**. It starts at callsound 0x4dec0, right after premap's last function enterlevel (0x4d950). It ends with checksectors 0x53df0–0x54bf0. 0x54c30 is SoundStartup, the start of sounds.c, so 0x54c30–0x5506f belongs to sounds, not sector.

Decompiles are in `<scratch>/g13/sector/<addr>.c`. I checked the key points against capstone disassembly of `full13.bin` (image base 0x10000), using the script `<scratch>/disx.py`.

### ps[] layout notes for 1.3D (stride 0x552)
The decompile only makes sense with these offsets, so they are worth recording:
- There is no int `aim_mode` at 0x280; it is a byte at 0x534.
- From `ang` onward fields sit 4 bytes earlier than ours: ang 0x280, oang 0x282, cursectnum 0x286, last_extra 0x28a.
- `ammo_amount` starts at 0x28c (11 entries) and curr_weapon is at 0x2a8.
- From `newowner` through `one_eighty_count` fields sit 10 bytes earlier than ours: newowner 0x2b2, hurt_delay 0x2b4, access_incs 0x2be, access_wall/sprite 0x2c4/0x2c6, kickback_pic 0x2c8, got_access 0x2ca, firstaid 0x2ce, i 0x2d4, one_eighty_count 0x2de, cheat_phase 0x2e0, quick_kick 0x2e6, heat_amount 0x2e8, timebeforeexit 0x2ec.
- `weaprecs` is [256], so: interface_toggle_flag 0x4f2, show_empty_weapon 0x4f8, scuba 0x4fa, jetpack 0x4fc, steroids 0x4fe, holoduke_on 0x502, weapon_pos 0x506, transporter_hold 0x50a, last_full_weapon 0x50c, boot 0x510, scream_voice 0x512, gm 0x516, inven_icon 0x52a, buttonpalette 0x52b, jetpack_on 0x52c, heat_on 0x531, holster 0x532, gotweapon 0x535 (11 entries), toggle_key_flag 0x545, hard_landing 0x549, secret_rooms 0x54b, pals 0x54c, return_to_center 0x551.

Globals: screenpeek 0x14deaa, myconnectindex 0x26727a, connecthead 0x267274, connectpoint2 0x2671f0, headspritestat 0x2519b8, headspritesect 0x2521b8, animatecnt 0x14c59c, animatesect 0xdd3d8, animateptr 0xdd458, animatevel 0xdd598, animategoal 0xdd698, haltsoundhack 0x14f734, numanimwalls 0x14deba, animwall 0x1414c0, numcyclers 0x14deb6, cyclers 0x124510, sync 0x14c0c0 (stride 10), max_player_health 0x14d7cc, camsprite 0x14deae, ud.multimode 0x14dde4, ud.player_skill 0x14de7e, ud.coop 0x14de32, ud.cashman 0x14d856, ud.lockout 0x14de3a, ud.pause_on 0x14dddc, ud.from_bonus 0x14ddde, level/volume/m_level 0x14de82/0x14de86/0x14de76, freezerhurtowner (probably) 0xc79d0, Sound[] 0x14c5e1 (13 bytes per entry, `.num` field).

Two further notes:
- **RNG order in our tree is undefined.** 1.3D's Watcom pushes EGS stack arguments right to left (zvel, xvel, ang, picnum), then the register args (z, y, x). Our EGS calls with several TRAND arguments (cactus, hanglight, satellite) depend on whatever order the compiler picks.
- **Atomic-only tiles that our C special-cases and 1.3D lacks:** DOORTILE23; SCREENBREAK14–19; W_TECHWALL5–9/11–14; W_MILKSHELF (and the HITTECHWALL10/15/16 targets); GENERICPOLE2; PANNEL3/BPANNEL3; TRIPODCAMERA; JURYGUY; BOSS4; FEM10; TOUGHGAL; GROW_WEAPON.
