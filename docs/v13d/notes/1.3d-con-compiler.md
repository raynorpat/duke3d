## 1.3D vs ours: CON compiler differences

I compared the 1.3D compiler (Ghidra output plus capstone disassembly of `~/Projects/ref/ghidra/full13.bin`) against `source/gamedef.c`. I modified no repo files.

**Correction to the brief:** the `case` labels in `34410.c` are **keyword index + 1**, not the keyword index. The code does `bVar7 = (char)tw + 1` and switches on that (`34410.c:47-56`, disasm `0x34440 inc al; cmp al,0x62`). So `case 0` is tw == -1, `case 2` is `actor`, `case 0x3d` is `gamestartup`, and so on. I dumped the jump table at `0x34210` and grouped it by target. Every keyword group matches ours exactly: the 1-transnum group, the 2-transnum group, the no-op group, the 1-param-if group, the no-param-if group, `ifpinventory` (transnum then fall into the 1-param ifs) and `hitradius` (5 transnums). Indices above 97 go to the same path as -1.

**Globals identified:**
- `textptr` = `0x14c5d4`, `scriptptr` = `0x14d788` (starts at `&script[1]` = `0x106304`)
- `labelcnt` = `0x14c5c4`, `label` = ptr `0x14c5d0`, `labelcode` = ptr `0x14c5b4`
- `line_number` = `0xd2fe2`, `total_lines` = `0xd2fe4`
- `error` = byte `0x14e514`, `warning` = byte `0x14e513`
- `parsing_actor` = `0x14c5cc`, `parsing_state` = `0xd2fe6`, `num_squigilly_brackets` = `0xd2fe0`, `checking_ifelse` = `0xd2fe7`
- `last_used_text` / `last_used_size` = `0xd2fc0` / `0xd2fd4`
- `loadfromgrouponly` = `0x14e510`, `max_ammo_amount` = `0x14d7a0`

**Helpers:**
- `33e30` = `getlabel`, `33ec0` = `keyword`, `33f40` = `transword`, `34050` = `transnum`
- `33a30` = `isaltok`, `33a00` = `ispecial`
- Watcom ctype mask `0xe0` = isalnum, `0x20` = isdigit

### Checked and identical

These match in parameter count, storage order and encoding, and in their error/warning counting:

- **Helpers and comments:** `transnum` (including the same bug of checking `label+(labelcnt<<6)` against keywords, and atol for digits or `-`), `getlabel`, `ispecial`, `isaltok`, `keyword` (returns 0 at EOF), `transword` storing the index first, `//` (20) skip to LF, `/*` (39) scan with line counting.
- **actor (1):** `scriptptr--`, transnum picnum, `actorscrptr[pic] = parsing_actor`. It reads up to 3 defaults (strength, action, move) into `parsing_actor[0..2]`, padding with `scriptptr += 4-j` on a keyword. Slot 3 is the OR of the remaining flags. It also resets num_squigilly_brackets and checking_ifelse, with the same two error checks. Verified in disasm `0x35067-0x3519b`.
- **Definitions:** `ai` (24) defines 3 slots with the 3rd being an OR of flags, or does 1 transnum inside actor/state. `action` (7) defines 5 slots padded with 0, or 1 transnum. `move` (32) defines 2 slots padded, or transnum plus an OR-flags word inside actor/state. `state` (17) definition stores `labelcode = scriptptr-1` and sets parsing_state. A `state` reference stores the absolute `labelcode`, with the same not-found error. `define` (19) uses `scriptptr -= 2` and gives a duplicate warning.
- **Block and actor/state control:** `ends` (18) has 3 checks. `enda` (4) checks no actor and more `{` than `}`, then clears parsing_actor. `{` (29) recurses. `}` (30) returns 1 and raises an error if the count goes below 0. `break` (12) and the other no-op keywords leave the keyword word in place. `palfrom` (14) takes 4 params padded with 0.
- **ifs:** all if-variants (`ifrnd` and the other 1-param ifs; `ifpinventory` with 2; the no-param ifs; `ifp` with OR-flags) lay out as: keyword, [params], fail slot holding an **absolute** pointer, comment skip, body, then `checking_ifelse++`. Verified in disasm `0x35263-0x352ef`.
- **Text keywords:** `definequote` (79) has a limit of 192 and 64 chars, terminated at `[i]`. `betaname` (76) is read up to LF.
- **passone:** the >12 errors+warnings check is the same.

All other keywords the 1.3D CONs use are in the 1-transnum, 2-transnum, 5-transnum (`hitradius`) and no-op groups, which match ours exactly.
