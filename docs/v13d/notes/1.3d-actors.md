# actors.c: 1.3D vs our source

**Summary:**
- Every actors.c function in 0x248e0–0x339ff is mapped, and every move* function was compared.
- About 90 game-state differences turned up.
- Two subagents covered moveeffectors: lotags 0–14 and 30, then 15 and up. I spot-checked their key claims against the disassembly.
- Nothing in the repo was modified.
- My working files are in `<scratch>/g13/actors/`:
  - decompiles: `<entry>.c`
  - disassembly: `27830.asm`, `29880.asm`, `2a5e0.asm`, `2b310.asm`, `me_dis.txt`
  - disassembler script: `<scratch>/xdis.py`

## Findings that affect other modules

- **RANDOMSCRAP (duke3d.h:158) is different in 1.3D.** The 1.3D macro is `EGS(s->sectnum, s->x, s->y, s->z-(12<<8), SCRAP6+(TRAND&15), -8, 48, 48, TRAND&2047, (TRAND&63)+64, -512-(TRAND&2047), i, 5)`.
  - It makes 4 krand calls per scrap; ours makes 7.
  - x and y are not jittered, and z is a fixed `-(12<<8)`.
  - The krand order is zvel, xvel, ang, picnum, because Watcom evaluates arguments right to left.
  - This holds in every actors.c use (confirmed in movefallers asm 0x277a3–0x277ff, TRIPBOMB, SE13, SE33) and probably in sector.c and others too.
- **1.3D player_struct (stride 0x552) differs from ours.**
  - It has no aim_mode, subweapon or wantweaponfire, and weaprecs has 256 entries.
  - MAX_WEAPONS is 11: ammo_amount is at 0x28c, wackedbyactor at 0x2a2, and gotweapon at 0x535.
  - Other offsets: curr_weapon 0x2a8, holoduke_amount 0x2b0, kickback_pic 0x2c8, i 0x2d4, heat 0x2e8, scuba 0x4fa, jetpack 0x4fc, weapon_pos 0x506, boot 0x510, inven_icon 0x52a, holster 0x532.
- **gc is not used.** Where ours uses gc, 1.3D has hardcoded constants:
  - 176 (gc)
  - 29 (gc/6)
  - 64 (gc-112)
  - 128 where ours uses gc-50 (126 if gc is 176)
  - 4 where ours uses gc>>5 (5)
  - 8 where ours uses gc/13 (13)
  - 52 where ours uses gc/3 (58)

  So several of these do not match even when gc is 176.
- **activatebysector in sector.c (1.3D 0x50e80)** returns after the first ACTIVATOR. Ours triggers every ACTIVATOR in the sector (the `return` is commented out).
- **spawn (game.c)**, flagged by the moveeffectors subagents:
  - 1.3D stores the original ceilingz in SE25's t[4]. Ours sets t[4] to 1 as an on/off flag.
  - 1.3D has no SE18 or SE28.
  - 1.3D SE6/14 uses a hardcoded SUBWAY sound, so 1.3D spawn may skip `callsound`. That call can change a MUSICANDSFX sprite's T1.
- **0x339b0 is getincangle.** Ours lives in gamedef.c and is equivalent. The gamedef boundary is probably 0x339b0, not 0x33a00.
- **C argument evaluation order.** Watcom evaluates EGS/cansee arguments right to left, and that fixes the krand order (for example lotsofmoney does angle first, then z). Our C code leaves the order to the compiler, so the variant must force right to left in every multi-TRAND call.
- **Address notes from the subagents:**
  - fricxv is 0x14d7d4 and fricyv is 0x14d7d0.
  - truefz is at ps+0x25c.
  - numplayers is 0x267278.
  - ud.clipping is 0x14d85c.
  - po[] is 0x11bc30.
